# react-runtime Specification

## Purpose

为专家数据生成、训练采样、普通推理和评测提供一致的文本 ReAct 行为契约，使相同动作面对相同初始世界时产生一致的状态和轨迹。契约同时保护模型与环境的职责边界；本次实现这些代码能力，但验收仅使用仓库已有材料，不要求生成新数据、补齐真实 tokenizer 或实际执行完整任务集。

## Requirements

### Requirement: 明确的动作与解析结果

系统 SHALL 区分合法工具调用、明确 FINISH 与解析失败。工具调用 MUST 包含字符串工具名和 JSON 对象参数；系统 MUST 拒绝格式不合法的动作，不猜测工具名、不默认选择第一个工具、不将解析失败转换为 FINISH。未知工具和不合法业务参数 MUST 产生明确错误且不得执行未授权的工具。

#### Scenario: 无法解析模型动作
- **WHEN** 输出缺少合法 Action、包含坏 JSON 或参数不是对象
- **THEN** 轨迹记录解析失败并结束该次交互，不执行工具，不记录成功 FINISH

#### Scenario: 终止标记的精确匹配
- **WHEN** 模型给出大小写或空白不同的完整 FINISH，或者不携带实际工具参数的 JSON 包装 FINISH
- **THEN** 系统将其识别为结束请求，不计入工具调用序列

#### Scenario: 终止前缀和框架标记
- **WHEN** 模型输出仅以 FINISH 开头的其他文本，或将 FORCE_STOP、ERROR 当成完成动作
- **THEN** 系统不将其识别为成功 FINISH，并保留相应的失败原因

### Requirement: 环境独占观测来源

模型输出 SHALL 只提供当前一步的 Thought 和 Action；Observation MUST 来自实际环境执行。系统 MUST 阻止模型续写的 Observation 或其后动作被当作真实工具结果或后续调用执行。

#### Scenario: 模型伪造后续交互
- **WHEN** 模型在一个响应中生成 Action 后继续生成 Observation 和另一条 Action
- **THEN** 系统最多处理环境观测边界之前的当前动作，忽略伪造反馈与后续动作，真实反馈仍由环境提供

### Requirement: 一致的任务初始化与状态转移

所有入口 SHALL 以相同任务初始化规则恢复会话，统一维护搜索候选、论文引用、最近操作对象及下载和翻译状态。初始化步骤 MUST 不计入策略工具序列、奖励动作和训练标签；只允许模型看到过滤后的必要初始状态，不暴露任务标识、标准步骤、预期对象或评分字段。

#### Scenario: 带已有会话的指代任务
- **WHEN** 任务在初始化后使用序号、论文 ID、标题或空引用指向论文
- **THEN** 数据生成、训练和推理解析到相同论文；初始化不增加策略动作数，模型输入不包含标准答案

#### Scenario: 离线关键词未命中
- **WHEN** 离线后端返回带 fallback 标记而非真实命中的结果
- **THEN** 系统提供明确失败反馈，不用 fallback 论文覆盖当前候选列表或最近操作对象

### Requirement: 明确的离线与在线执行模式

系统 SHALL 显式区分离线回放、真实工具执行和快照录制。离线回放 MUST 不联网、不启动真实翻译进程，快照缺失时 MUST 报错而非自动转入在线模式。真实翻译 SHALL 在工具调用返回前得到完成或失败结果；离线模拟完成 MUST 标记模拟来源，不声称产生了真实 PDF。

#### Scenario: 离线输入缺失
- **WHEN** 离线运行指定的快照不存在或所需记录不可用
- **THEN** 系统报告缺失数据或明确的未命中，不向网络或真实翻译服务自动补请求

#### Scenario: 翻译后读取译文或缓存
- **WHEN** 同一轨迹成功完成真实翻译或有效离线模拟翻译后继续查询对应状态
- **THEN** 后续工具读取到一致的完成状态，结果区分真实与模拟来源，不依赖异步 Web 队列或 SSE

### Requirement: 每轨迹状态与产物隔离

每条轨迹 SHALL 拥有独立可变会话和产物空间，共享快照及预取资产 MUST 被视为只读。重置或清理一条轨迹 MUST 不改变其他轨迹、用户现有文件或快照构建任务产生的文件。

#### Scenario: 同组并行轨迹
- **WHEN** 同一任务的多条采样交错执行搜索、下载和翻译
- **THEN** 各轨迹只看到自己的会话变化；重置任一轨迹不改变其余轨迹的引用和产物

#### Scenario: 清理结束轨迹
- **WHEN** 轨迹结束后执行清理
- **THEN** 仅清理该轨迹拥有的临时产物，共享基线文件和用户文件保持不变

### Requirement: 稳定观测与可审计轨迹

系统 SHALL 分别保存工具结构化结果与模型可见观测，并使用共同的确定性规则生成可见文本。裁剪长正文时 MUST 保留动作判定需要的对象标识、引用映射、状态和错误信息，并记录裁剪事实。轨迹 SHALL 包含原始模型输出、实际动作、环境结果、错误与终止原因；框架会话标识不得被写入策略学习的动作参数。

#### Scenario: 长工具结果
- **WHEN** 工具正文超过模型可见长度预算
- **THEN** 可见正文按统一规则裁剪，必要标识与状态仍完整，审计结果保留原始结果及裁剪信息

#### Scenario: 框架注入会话标识
- **WHEN** 工具执行需要内部会话标识
- **THEN** 标识仅在执行边界注入，不进入模型生成的 Action、SFT 标签或业务参数评分

### Requirement: 结束原因与任务成功分离

系统 SHALL 分别记录模型 FINISH、解析失败、运行错误和轮数或 token 预算耗尽。FINISH MUST 不自动表示任务成功；受阻任务仍须依据模型给出的具体原因和既有任务语义评分。默认完整任务预算 SHALL 至少覆盖 6 轮，且 FINISH 占用一轮。

#### Scenario: 最长任务正常结束
- **WHEN** 模型使用 5 次必要工具调用并在第 6 轮 FINISH
- **THEN** 默认预算允许其完成，不将最后的结束请求截掉

#### Scenario: 受阻任务或提前结束
- **WHEN** 模型在无法完成的任务上说明原因并 FINISH，或在应执行工具的任务上提前 FINISH
- **THEN** 评分依据具体任务判定正确拒绝或虚假完成，不仅凭 FINISH 给出成功

### Requirement: 版本化上下文与训练责任边界

统一协议 SHALL 使用相同的初始任务消息、assistant 动作消息和环境 Observation 消息序列，应用于 SFT、DPO、GRPO 与推理。SFT MUST 只监督当前目标 assistant 响应；DPO MUST 在共同 prompt 下仅对 chosen/rejected 的当前单条 assistant 响应计算偏好目标，不将历史、setup 或环境反馈计入目标；GRPO MUST 保留原始采样 token，模型 token 与环境 token 的损失掩码必须区分，且后续消息追加不能改写已有采样前缀。实际运行使用的模板无法保持前缀时 MUST 明确失败，不通过重新编码 GRPO 模型响应绕过。DPO 离线消息的训练编码 SHALL 校验实际模板和共同前缀，不冒充 on-policy 原始 token 重放。协议迁移 MUST 使用新协议版本；新增 DPO 数据 SHALL 使用独立数据标识并声明当前上下文协议，不静默混用不兼容训练数据或模型元数据。本次 SHALL 改造相应转换、标签、掩码及元数据代码，而不要求实际生成数据、训练或补齐 tokenizer；验证依据和未覆盖部分按工程验收规格记录。

#### Scenario: 同一历史到达下一决策点
- **WHEN** 数据生成、DPO 配对、GRPO 和本地推理在相同历史、协议和 tokenizer 下准备下一步输入
- **THEN** 得到相同的消息内容和上下文 token 前缀；外部 API 至少接收相同逻辑消息序列

#### Scenario: 多轮训练标签和掩码
- **WHEN** 训练样本包含先前动作与环境反馈
- **THEN** SFT 仅当前目标响应有监督标签，DPO 两侧均仅当前 assistant 参与偏好目标，GRPO 的环境反馈及运行时插入边界不参与策略 loss，GRPO 模型原始采样 token 不被重新编码替换

#### Scenario: 新旧协议混用
- **WHEN** 训练输入声明的协议与当前训练协议不兼容
- **THEN** 系统在训练前报告不兼容；跨协议评测必须显式标注，不能作为同口径复现结果

#### Scenario: 代码迁移但尚未生成新数据
- **WHEN** 本次仅完成协议适配及数据转换代码改造，未执行数据生成或真实 tokenizer 集成
- **THEN** 历史数据和 manifest 保持原样，现有材料检查与未验证集成分别记录，不为验收合成样本、token 或轨迹

### Requirement: 单步偏好要求实际完整上下文一致

系统 SHALL 仅在同一任务、初始化、快照、来源模型、协议和采样设置下比较真实轨迹，且配对双方当前实际请求的完整消息序列 MUST 完全一致，包括角色、顺序、任务/工具说明、可见 setup、历史 Thought/Action 及环境 Observation 的原文本。系统 MUST 不通过忽略 Thought、只比较动作、裁剪差异、归一化消息文本、近似匹配或补齐一侧历史达成匹配。每个轨迹组合 SHALL 只考虑其共同前缀下首个有效动作分歧；奖励差用于排序，不宣称已经证明单步因果优势。

#### Scenario: 动作历史相同但 Thought 不同
- **WHEN** 两条轨迹之前调用了相同工具，但模型在当前决策前实际看到的历史 Thought 文本不同
- **THEN** 当前决策不能配对，记录上下文不一致，不删除 Thought 后继续匹配

#### Scenario: 环境反馈或初始化不同
- **WHEN** 工具动作相同，但可见 Observation、setup 或来源环境身份不同
- **THEN** 该组合不产生偏好，记录对应来源或上下文差异，不借用另一轨迹的观测

#### Scenario: 当前动作相同而响应文本不同
- **WHEN** 在同一完整请求下，两侧当前动作相同但 Thought 或响应原文本不同
- **THEN** 本轮不作为动作偏好，且两条响应不会被视为后续轮次的共同历史；后续请求不一致时明确丢弃

#### Scenario: 共同完整前缀后动作不同
- **WHEN** 两侧当前请求完全相同，当前真实动作不同，双方响应和轨迹评分可用且奖励差严格超过配置阈值
- **THEN** 仅将该轮两条真实 assistant 响应构成候选，以高分轨迹为 chosen，保留两侧完整来源与当前轮次

### Requirement: 偏好目标必须是真实当前模型决策

chosen/rejected SHALL 各为实际模型生成的一条当前响应，使用共同运行时的策略文本边界，并能够解析为 CALL 或 FINISH。系统 MUST 不把模型续写的 Observation、框架终止标记、空响应或缺失步骤改造为训练目标；被 token 截断的当前响应 MUST 不作为完整决策配对。真实提前 FINISH SHALL 按实际轨迹评分参与比较，不能仅凭 FINISH 判断成功。缺失步骤、预算耗尽或错误 MUST 保持真实终止原因，不补造 FINISH。

#### Scenario: 短轨迹没有对应决策
- **WHEN** 一条轨迹在候选轮次之前耗尽预算或停止，缺少该轮模型响应
- **THEN** 丢弃该组合并记录缺失原因，不创建“任务完成”文本或 FINISH 作为替代

#### Scenario: 真实提前 FINISH
- **WHEN** 在完全相同的 prompt 下，一侧模型真实输出 FINISH，另一侧输出工具动作
- **THEN** 系统按实际轨迹奖励及差值条件决定是否形成偏好，不固定把 FINISH 视为正例或负例

#### Scenario: 模型续写虚假环境内容
- **WHEN** 原始模型响应在当前 Action 后续写 Observation 或后续动作
- **THEN** 仅使用共同运行时保留的当前策略文本，伪造观测与后续动作既不进入环境历史也不进入偏好目标

### Requirement: 偏好编码不得以截断改变上下文

训练前系统 MUST 使用实际 tokenizer 与模板审计共同前缀、两侧单条 assistant 目标和序列长度。prompt 中所有历史/环境内容 MUST 排除于当前目标的概率统计；超出配置预算或模板不能保持共同上下文时 MUST 明确失败，不通过左截断、右截断或删除任一侧内容继续训练。两侧在编码后不再包含有效目标时 MUST 拒绝。

#### Scenario: 长上下文超预算
- **WHEN** 原始配对满足完整上下文一致，但任一侧编码后的完整序列超过训练预算
- **THEN** 在优化前报告样本与长度并失败，不截去历史或动作以保留该对

#### Scenario: 模板改变前缀或目标边界
- **WHEN** 实际模板处理使两侧 prompt 前缀不同，或把历史 assistant/Observation 混入当前目标
- **THEN** 审计失败，不将不同条件下的概率或环境文本用于偏好优化
