# Proposal

主线架构重组与依赖分层

## Why

当前主线已收敛到 SFT、GRPO 和文本 ReAct，但通用运行环境仍反向依赖 benchmark 任务目录，训练与评测交叉依赖评分，GRPO 复用 SFT 命令文件的私有函数，数据脚本和包入口依赖 `sys.path` 注入。统一安装还会让仅使用 API 的用户安装整套训练栈；需要按职责和依赖方向重新组织，而不是继续围绕旧文件位置增加兼容层。

## What Changes

- **BREAKING**：改用 `src/agentic_arxiv/` 单一包命名空间、`pyproject.toml` 和 `agentic-arxiv` 统一命令；退出旧 `AgenticArxiv.*`、目录内模块执行和直接脚本入口，不提供旧命令或旧导入路径的转发层。
- 按运行时、工具、会话状态、模型后端、任务、评分、训练、评测和数据准备划分职责；共享数据契约及来源记录保持轻量，依赖方向由自动检查约束。
- 将任务依赖解析与初始化计划准备移出运行时；评分仅消费既有轨迹；SFT/GRPO 共用模型配置模块，但 GRPO 原始采样 token、mask 和训练器适配仍由训练侧负责。
- 将可复用数据与评测代码纳入包，CLI 只做参数解析、组件组装和交付；支持安装后的命令从不同工作目录运行，不再按源码文件层级猜测资产根目录。
- 将 API 基础依赖、本地推理和训练依赖分层，真实翻译、日志和开发检查按需安装；保留现有版本约束与缺失依赖保护，全部 10 个工具仍须完整注册。
- 区分长期资产检查和一次性维护审计；归档两个未纳入主线的旧行为基线文件，限定清理已确认的前端缓存和空目录，不删除研究证据。
- 迁移活动文档、测试与 CI，补充包安装、轻量导入、命令路径和依赖方向检查；不以生成新数据、加载真实模型、训练或完整任务执行作为验收方式。

## Capabilities

### New Capabilities

无。沿用已有能力分类；内部目录设计写入 design，不为文件搬迁新增业务能力规格。

### Modified Capabilities

- `training-mainline`：增加可安装包与统一命令的外部契约，细化 API、本地推理和训练安装层级、轻量帮助及可选依赖失败行为；支持的算法和训练语义不变。
- `research-validation`：增加架构依赖与安装隔离的验收要求，明确源码迁移、历史路径和非活动基线归档的证据保全边界。

## Impact

- 源码：涉及 `AgenticArxiv/agents`、`rl`、`benchmark`、`models`、`tools`、`utils`，常用 `scripts/*.py` 和 `eval/badcase_replay.py`；活动测试迁至根 `tests/`，维护脚本保留独立职责。
- 接口：命令名、Python 导入路径及内部调用接口允许改变；旧命令映射由新迁移说明提供，而不是修改历史报告中的命令字符串。
- 安装与开发：以 `pyproject.toml` 声明依赖和入口，替换混装 requirements 与 `PYTHONPATH` 工作流；更新 CI、活动 README 和运行指南。
- 不变项：10 工具的名称、业务参数与注册顺序，86 扩展任务、8 冒烟任务、既有切分，ReAct 消息与终止语义，协议版本及模板内容，SFT 标签、GRPO token/mask、奖励公式与显式训练配置传递。
- 资产：历史数据、manifest、快照、模型、轨迹和报告原位保全；新迁移清单另存，不覆盖上次迁移证据。唯一计划迁移的旧行为基线须逐字节保留并记录原路径，不重新运行或作为验收依据。
- 非目标：不新增算法、服务、工具或任务，不修订奖励与模型行为，不升级训练栈，不发布软件包，不运行数据生产、真实 tokenizer/模型评测或训练。
