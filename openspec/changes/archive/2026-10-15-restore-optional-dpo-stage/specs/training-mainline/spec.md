# Spec Delta

## MODIFIED Requirements

### Requirement: 受支持的训练与运行入口

系统 SHALL 保留 SFT、GRPO 和文本 ReAct 活动主线，并将 DPO 恢复为显式可选的中间阶段，不主动替换为另一种损失或训练算法。DPO 数据生成、训练和阶段验证 SHALL 均可使用，但 MUST 不被直接 SFT 到 GRPO 的默认命令隐式触发。OPD、PPO、自进化编排、独立 VLM 后训练、算法变体选择、Jev、MCP/Skill CLI 及 Web 服务的活动入口 MUST 保持退出，不借恢复 DPO 重新开放其他旁支。

#### Scenario: 使用主线入口
- **WHEN** 用户查看训练、普通推理或正式评测的帮助与活动文档
- **THEN** 可用入口围绕直接 SFT 到 GRPO、可选 DPO 与文本 ReAct 组织，不要求选择已退出的算法、Agent 架构或启动 Web 服务

#### Scenario: 使用已退出的入口
- **WHEN** 用户尝试使用除本次恢复的 DPO 外仍已移除的算法或服务入口
- **THEN** 该入口不可运行，迁移文档明确退出范围和受支持路径，不静默转为另一种算法

#### Scenario: 不选择 DPO
- **WHEN** 用户按原默认命令执行 GRPO，且未指定 DPO 模型
- **THEN** 默认仍读取 `outputs/sft_qlora/final`，不寻找 DPO 数据或模型，不启动 DPO 生成、训练或验证

### Requirement: SFT 到 GRPO 的直接模型交接

系统 SHALL 允许 GRPO 直接消费 SFT 产物及其 manifest，不要求中间 DPO 阶段；用户显式指定时 SHALL 允许 GRPO 消费当前协议的 DPO 产物及其 manifest。全参产物与适配器产物 SHALL 使用明确的模型加载契约；模型、必要元数据或协议信息缺失/不兼容时 MUST 报错，不静默退回其他本地模型或远程 API。DPO 来源 SHALL 保留其 SFT 起点和真实训练阶段，不能伪装为 SFT 产物以绕过检查。

#### Scenario: 加载 SFT 适配器产物
- **WHEN** GRPO 的输入是包含基座模型信息的有效 SFT 适配器产物
- **THEN** 系统按其元数据加载正确基座与适配器，并在 GRPO 产物中记录实际来源

#### Scenario: 指定的模型不存在
- **WHEN** 用户指定的训练模型路径或必需文件不存在
- **THEN** 训练在采样前失败并给出缺失项，不触发外部 API 推理或更换训练起点

#### Scenario: 显式使用 DPO 产物
- **WHEN** 用户将有效 DPO 全参或适配器产物显式指定为 GRPO 输入
- **THEN** 系统校验阶段、权重类型、基座声明与协议，加载该策略，并在 GRPO 记录中保留 DPO 及其 SFT 来源

#### Scenario: 旧 DPO 产物没有当前协议信息
- **WHEN** 用户指定缺少必要 manifest 或当前协议声明的历史 DPO 目录
- **THEN** 系统明确拒绝，不根据目录名补填阶段或协议，也不自动改用默认 SFT

### Requirement: 主线依赖与工具能力分离

核心训练和离线评测 SHALL 不依赖 Web、数据库、SSE、MCP 或 Jev 服务。系统 SHALL 分别提供 API 基础运行、本地模型推理和 SFT/DPO/GRPO 训练的安装层级，基础安装 MUST 不强制安装本地模型或训练栈，本地推理安装 MUST 不强制安装训练器和训练数据处理组件，训练安装 SHALL 包含其所需的本地推理能力。DPO 本地采样与偏好配对 SHALL 属于本地推理/数据能力，不要求安装训练器；DPO 训练 SHALL 明确要求训练安装层级。系统 SHALL 保留外部 LLM API 推理、真实 PDF 翻译、图表工具现有推理后端及其明确声明的可选依赖；缺少某个可选依赖时 MUST 在使用相应能力时给出明确错误和安装指引，而不是让工具注册静默缩水。依赖重组 MUST 保持现有版本约束及算法接口保护，不借安装分组升级、降级或替换训练实现。

#### Scenario: 最小研究环境
- **WHEN** 环境没有安装 Web、数据库、MCP 和 Jev 相关组件，且已安装请求操作对应的依赖层级
- **THEN** SFT、可选 DPO、GRPO、普通 ReAct 命令和离线评测按各自能力加载受支持入口，工具注册检查仍覆盖全部 10 个工具

#### Scenario: 请求未安装依赖的在线工具
- **WHEN** 用户显式执行需要可选依赖的真实翻译或图表推理
- **THEN** 系统要么执行对应真实工具，要么报告该依赖缺失及安装方式，不返回伪造的成功产物

#### Scenario: 只使用外部 API 与历史记录
- **WHEN** 用户仅安装基础能力，使用 API 推理入口或读取已有轨迹进行重评分
- **THEN** 系统不加载本地模型或训练依赖，10 个工具的业务声明仍完整；真实工具的可选后端只在被明确使用时检查依赖

#### Scenario: 本地推理缺少训练组件
- **WHEN** 用户安装本地推理能力但未安装训练组件，选择已有本地模型推理后端或 DPO 数据生成
- **THEN** 操作不为导入训练入口或回调而要求安装训练器；若随后请求训练，在训练开始前说明缺失依赖，不改用远程 API

### Requirement: 可安装包与统一命令入口

系统 SHALL 以可安装的 Python 包提供唯一受支持的 `agentic-arxiv` 命令族，覆盖普通 ReAct、任务 rollout、数据准备、SFT、可选 DPO、GRPO、评测和现有诊断能力。DPO SHALL 通过 `data dpo generate` 和 `train dpo` 提供生成与训练，并由训练阶段提供默认验证及显式跳过开关。安装后的使用 MUST 不要求用户修改 Python 搜索路径或切换到特定源码子目录。旧命令与旧导入命名空间 SHALL 保持退出，不提供旧入口兼容保证。除本次明确恢复的 DPO 行为外，命令重组 MUST 保持既有操作的默认参数、配置优先级、执行模式、输出内容与失败条件，不引入算法或业务语义变化。

#### Scenario: 从非源码目录使用安装包
- **WHEN** 用户已安装包，在其他工作目录查看命令帮助或执行具有明确输入路径的操作
- **THEN** 命令能够解析和加载受支持能力，不依赖仓库源码目录进入 Python 搜索路径，也不从安装位置猜测研究资产所在目录

#### Scenario: 查询未安装训练依赖的帮助
- **WHEN** 用户仅安装基础能力并查看根命令、SFT、DPO、GRPO 或本地推理相关子命令的帮助
- **THEN** 系统显示用法和所需安装层级，不加载模型、执行工具、读取研究数据或因未安装训练依赖而中断帮助

#### Scenario: 迁移旧操作
- **WHEN** 用户依据迁移说明使用新命令
- **THEN** 既有受支持操作保留原参数与结果语义；DPO 恢复按新协议及严格配对要求执行，旧命令或历史记录不被偷偷改写成新协议运行证据

### Requirement: 显式工作区与资产路径

系统 SHALL 区分安装包内的默认配置与用户工作区内的输入和输出。用户 SHALL 能显式指定工作区；未指定时以当前工作目录为工作区。用户传入的相对配置、模型、数据、快照和输出路径 SHALL 相对于该工作区解释，绝对路径保持原义。既有 SFT/GRPO 默认训练配置的有效内容 MUST 保持不变，DPO 新默认 SHALL 单独记录；研究资产 MUST 不随安装包复制、下载或合成。缺失输入 SHALL 报告实际解析路径，不自动搜索其他仓库、使用不同模型或联网补齐。

#### Scenario: 相同工作区从不同目录调用
- **WHEN** 用户在两个不同目录指定同一工作区和相同相对输入路径
- **THEN** 系统解析到同一输入，包的安装位置不改变默认训练配置或数据、模型和产物的归属

#### Scenario: 离线工作区缺少快照
- **WHEN** 用户请求离线操作，但指定工作区没有所需快照
- **THEN** 系统报告缺失快照的解析位置并失败，不从源码目录回退读取、不调用在线工具，也不创建替代快照

## ADDED Requirements

### Requirement: DPO 配置扩展兼容既有训练配置

系统 SHALL 为 DPO 提供独立、可记录的默认配置，并继续接受原有仅包含 SFT/GRPO 的有效配置文件。缺少整个 DPO 节时 SHALL 使用并记录包内 DPO 默认，不能改写用户文件或更改既有阶段值；显式 DPO 节 MUST 接受完整字段和类型校验，未知或缺失字段不能静默忽略。显式 CLI 参数 SHALL 继续优先于配置，显式训练参数不被当前依赖支持时 MUST 在训练前报错。

#### Scenario: 使用原有用户配置
- **WHEN** 用户指定本次恢复之前的有效 SFT/GRPO 配置
- **THEN** 原阶段配置与默认起点不变；执行 DPO 时使用有来源记录的 DPO 默认，不要求先编辑文件

#### Scenario: 显式配置字段错误
- **WHEN** DPO 配置含未知字段、错误类型或当前训练接口不支持的显式参数
- **THEN** 系统列出错误并拒绝训练，不通过删除参数或切换算法继续

### Requirement: DPO 使用冻结的完整 SFT 参考策略

DPO SHALL 从与偏好数据来源一致的当前协议 SFT 产物初始化策略与参考策略。参考策略 MUST 包含该 SFT 产物全部已学习权重，在整个优化期间冻结且不进入优化器；策略更新 MUST 不改变参考权重。适配器输入 MUST 包含正确基座与 SFT adapter，不允许以原始基座或随机新 adapter 代替 SFT 参考。系统 SHALL 提供默认 QLoRA 与显式全参资源路径，并复用单进程/DDP 的设备、资源记录和主进程副作用边界；资源策略不能改变参考身份或切换损失算法。

#### Scenario: 从 SFT adapter 开始 DPO
- **WHEN** 输入为有效 SFT adapter 且使用 QLoRA
- **THEN** 策略继续该 SFT 权重，参考保持同一 SFT 行为；仅策略的允许参数可训练，不能通过关闭所有 adapter 得到原始基座作为参考

#### Scenario: 执行策略更新
- **WHEN** DPO 执行优化更新
- **THEN** 参考参数不获得优化更新，也不因与策略共享可变参数而变化

#### Scenario: 多进程保存与验证
- **WHEN** DPO 在 DDP 下完成训练或阶段验证失败
- **THEN** 记录实际全局偏好对批量，各进程使用各自设备，公共报告只由主进程写入，主进程验证结果或错误传递给其余进程，不重复验证或无限等待

### Requirement: DPO 训练审计与产物来源完整

DPO 训练 MUST 在优化前校验数据包完成状态、内容哈希、记录数、任务切分、源模型、协议、完整上下文与单步目标。协议、来源不一致、空数据、非有限分数或不完整数据包 MUST 明确拒绝，不能用跳过完整性检查绕过严格配对。系统 SHALL 提供只审计而不加载策略权重或执行训练的模式。最终产物 SHALL 明确声明 DPO 阶段和全参/适配器类型，记录数据、SFT 起点、冻结参考来源、配置、资源、依赖、实际步数和停止原因；导出的策略 MUST 不夹带参考权重作为可训练产物。

#### Scenario: 仅检查训练输入
- **WHEN** 用户选择 DPO 的只审计模式
- **THEN** 系统检查数据、来源、协议及实际模板下的长度/目标边界，报告结果，不加载策略权重、不创建训练 checkpoint

#### Scenario: 数据来源与模型不符
- **WHEN** 数据声明的源 SFT 或模板与当前训练起点不一致
- **THEN** 在训练前明确拒绝，不覆盖数据的来源字段或改用另一模型

#### Scenario: 导出 DPO adapter
- **WHEN** DPO QLoRA 完成并导出最终策略
- **THEN** 产物有正确基座声明、策略 adapter、tokenizer 与 DPO manifest，可被显式 GRPO 输入识别，参考权重不混入策略 adapter
