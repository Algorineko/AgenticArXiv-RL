# Design

## Context

动机与恢复范围见 [proposal.md](proposal.md)。以下事实来自当前源码与删除前的 Git 内容，不代表训练效果已验证：

| 位置 | 相关现状 |
| --- | --- |
| `974b655^:AgenticArxiv/rl/train_dpo.py`、`scripts/generate_dpo_data.py` | 旧版有训练、分歧步配对和阶段验证，但配对仅比较动作，短轨迹会补 FINISH；使用旧单字符串上下文、旧包路径，生成侧没有当前训练切分保护。 |
| `runtime/agent_engine.py`、`runtime/react_contract.py` | 已有 `react-runtime-v2` / `react-messages-v3`，记录真实 `policy_text`、`visible_observation` 和终止原因；共同运行时不读取任务答案。 |
| `data_pipeline/generate_sft_data.py`、`tasks/initialization.py` | 已有训练切分选择、初始化、样本指纹与数据 manifest 模式，可复用规则，但 DPO 不能使用专家动作作为模型响应。 |
| `training/grpo.py` | 产物校验目前只接受 SFT/GRPO；包含全参/适配器检查与策略加载实现，DPO 不应反向导入这一训练入口。 |
| `training/model_setup.py`、`distributed.py` | 已有 QLoRA、设备绑定、有效批量、主进程写入和异常广播机制。 |
| `training/mainline_config.py`、`resources/mainline.json` | 顶层字段严格限定为 SFT/GRPO，新增 DPO 不能让现有用户配置失效。 |
| `training/stage_verifier.py`、`evaluation/episode.py` | 已有多轮阶段验证与报告；聚合器当前尚未暴露虚假完成率，模型加载也需明确复用产物契约。 |
| `tests/test_architecture.py` | 数据层不能导入训练或评测编排层；训练入口不能成为另一阶段的共享库。 |

本地 `.venv` 未安装 TRL、Transformers、PEFT，本轮没有真实训练库集成证据。API 设计参考仓库资源保护中列出的 [TRL 0.29.1 DPO 文档](https://huggingface.co/docs/trl/v0.29.1/dpo_trainer)及其 [DPOTrainer 源码](https://github.com/huggingface/trl/blob/v0.29.1/trl/trainer/dpo_trainer.py)：支持显式消息 prompt/chosen/rejected 和显式参考模型；实现时仍需检查实际安装接口，不能把文档阅读当作本地验证。

## Goals / Non-Goals

**Goals:**
- 采用现有分层和协议，增加可审计、可跳过的 DPO，而不改变直接 SFT/GRPO 的参数与执行语义。
- 把“同一完整上下文”“实际模型决策”“冻结 SFT 参考策略”落实为数据和加载的拒绝条件，而不是仅靠文档约定。
- 将训练、数据质量诊断、阶段阈值和模型效果结论分开记录。

**Non-Goals:**
- 不增加新的运行时、环境克隆/分支采样器、人工负例器或训练调度器。
- 不把旧轨迹补字段后重新标为当前协议；不支持任意第三方偏好数据自动导入。
- 不增加 FSDP/DeepSpeed、参考策略动态更新、参考分数缓存或其他 DPO 损失变体。

## Decisions

### 1. 保持现有依赖方向，复用能力而不是旧入口

- 新增 `data_pipeline/dpo_pairs.py` 放生成侧纯配对/诊断逻辑，`data_pipeline/generate_dpo_data.py` 负责本地模型采样与落盘；通过现有 CLI 注册 `data dpo generate`。数据包与行结构的跨层校验放在现有 `provenance`/`contracts` 边界，消息验证复用 `runtime/react_contract.py`；训练层不反向导入数据生成层。
- 生成器直接编排 `ReActAgent`、任务初始化、独立 `AgenticArxivMultiTurnEnv` 和 `RewardCalculator`，不导入 `training` 或 `evaluation`。若任务选择规则抽取到 `tasks`，只抽取共享规则，不改变 SFT/GRPO 的选择范围。
- 将当前 GRPO 中必要的纯产物元数据校验放入 `llm/artifacts.py`，使用 `provenance` 和 `config`；设备与训练策略加载留在 `training/model_setup.py`。本地生成与阶段验证复用明确的全参/适配器推理加载，不引入训练依赖。
- 新增 `training/dpo.py` 作为独立入口；CLI 的帮助、能力检查和路径解析仍延迟加载重依赖。更新架构检查的入口枚举，而不放宽依赖白名单。

不采用恢复旧 `AgenticArxiv/rl/` 或让 DPO 导入 `training/grpo.py` 的办法，因为它们分别破坏唯一命令与阶段边界。

### 2. 第一版只生成来自本地 SFT 的离线训练偏好

输入必须是带当前协议 manifest 的本地 SFT 产物、已有快照及显式版本化 `:train` 切分；任务来自 expanded 定义。没有隐式 basic、全量 86 任务或 GRPO 信号子集回退。加载后核对实际 tokenizer 模板；任一协议或来源错误在采样前失败。

每个任务执行多条相互隔离的完整 episode，使用同一任务初始化计划、只读快照及固定评分配置。使用现有 `start_generation_stream`，按任务 ID 和 trial 建立可复现且彼此不同的采样流。先后调用顺序或某轨迹变长，不得让下一条轨迹重复使用同一随机流。

在数据层增加轻量客户端记录适配器，透传现有客户端协议并深拷贝每次实际发送的 messages，绑定实际返回响应和对应历史步骤。这样比较的是模型真正看到的输入，而不是仅凭 action 重新拼接的假定历史；适配器不改变消息、不增加模型请求、不重放工具。标准步骤和评分参考只在初始化/评分侧使用，不进入模型消息。

评分只读取实际轨迹，保留现有奖励公式与失败上限。默认固定 `curriculum_steps=30`、`training_step=0`，与旧生成调用的默认口径一致；记录有效权重与评分源码标识，DPO 优化步数不改变已生成偏好。后续若另行调整采样或评分配置，产生新 manifest，不覆盖已有批次。

不选在线工具或外部 API 生成作为首版入口，避免把可变环境/不同策略来源混进严格上下文配对。

### 3. 精确上下文与首个真实动作分歧

对同一任务、初始化、快照、源模型、协议和采样设置下的每个无序轨迹组合，最多产生一个候选：

1. 校验来源与记录完整性，再按轮次检查两条轨迹的实际请求。messages 的角色、顺序及每段 content 必须逐项一致；指纹用于索引，不能替代原值检查。比较保留空白、历史 Thought、Action 文本、环境 Observation 和 setup，不做语义相似或动作归一化后放宽匹配。
2. 若当前完整请求不同，记录 `context_mismatch`，该轨迹组合结束。不能跳过前缀差异寻找更晚的“相同状态”。
3. 当前响应取运行时已有的 `policy_text`，不把 raw response 中越过 Observation 边界的内容算成真实反馈。候选双方必须各有一个真实、非空、未被 token 截断、可解析为 CALL 或 FINISH 的当前响应。框架生成的 ERROR、MAX_TURNS 等不能充当候选。
4. 当前动作归一化仅用于判断是否存在动作决策差异，不用于改写 messages 或目标文本。动作相同但 Thought/原文本不同的当前轮不产出偏好，也不能把它们视为后续轮次的共同前缀；若后续实际 messages 不同，仍按 `context_mismatch` 丢弃。
5. 第一个满足上述条件的不同动作成为唯一候选决策点；两条真实轨迹的有限奖励之差必须严格大于 `min_reward_gap`。完整轨迹可能在后续发生业务失败、解析失败或预算耗尽，保留真实结果用于排序；缺失记录、模型调用异常或无法可靠评分的 rollout 记为无效，不当成自动低分负例。
6. 奖励较高的一侧为 chosen。真实提前 FINISH 可以成为 rejected，正确拒绝也可以成为 chosen，均由实际评分决定；短轨迹缺少当前响应时记录缺失，绝不补 FINISH。

第一版保留旧版“每任务最多一个有效对”的采样权重：对该任务的所有有效候选按奖励差降序选择，平局按轮次、trial ID 稳定打破；其他有效候选记录为 `not_selected`，不混入无效原因。跨任务不去重合并，防止混淆来源；同任务相同 prompt/chosen/rejected 指纹重复时去重并统计。

完整轨迹奖励只是偏好排序信号，不能据此宣称单步动作具有已证实的因果优势。整轨迹目标或从共同前缀主动分支采样需要另一变更。

### 4. 数据包和诊断口径

每次显式生成写入一个新批次的数据 JSONL、`.traces.jsonl`、`.manifest.json` 和 `.report.json`。训练行含 `prompt` 消息列表及各一条 assistant 的 `chosen` / `rejected`，另存协议、任务/切分、决策轮次、两条 trace ID、分数/奖励差、完整上下文与样本指纹。训练器只接收三列训练内容，其余字段用于审计，不泄露到 prompt。

manifest 固定新的数据 kind/version，绑定数据与轨迹文件哈希、样本数、源 SFT 及其 manifest、tokenizer/协议、任务定义/切分、初始化、快照、采样随机种子和预算、评分配置、配对算法版本。历史 DPO 字符串数据不兼容，不静默迁移。

诊断同时提供两个分母，避免只汇报过滤后的好看比例：
- 任务产出率 = 有最终偏好对的任务数 / 请求生成的训练任务数。
- 组合接受率 = 通过配对条件的组合数 / 请求的无序轨迹组合数。所有请求组合均进入统计；采样失败导致无法形成组合时也计入相应无效桶。

分别记录请求/完成/无效 rollout 数、请求/通过/丢弃组合数、去重数、有效但未选数、最终对数及每任务细分。每个组合有且仅有一个首要结果码，详细原因可附加，不重复加入总数；检查结果码总和等于请求组合数。原因至少区分采样失败、来源或协议不一致、记录缺失、上下文不一致、缺少当前响应、不可用/截断决策、无动作分歧、非有限分数、奖励差不足及重复样本。

零有效样本时保留真实轨迹与失败报告、返回非零，不发布可训练数据/成功 manifest。少量有效样本时按阈值报警并保存完整报告，不自动重采样或修改条件。输入级校验失败不产生伪“空跑”轨迹。已有目标文件拒绝覆盖；先写临时文件、最后发布成功 manifest，训练入口拒绝未完成批次。

### 5. 明确模型加载与冻结参考策略

DPO 策略和参考策略从同一个、与数据来源指纹相符的 SFT 产物独立加载。只允许声明为 SFT 的当前协议产物作为本阶段起点，不根据目录名猜测 stage，不接受原始基座替代缺失 SFT。

- 默认 QLoRA：输入为 SFT adapter 时，策略在同一基座上继续训练该 adapter；参考模型为另一份同一基座与同一 SFT adapter，全部冻结并设为评估模式。输入为全参 SFT 时，策略在该产物上建立可训练 LoRA，参考模型保留该完整 SFT 行为。
- 显式全参：SFT adapter 按其元数据加载并合并到各自独立模型；策略可训练，参考模型冻结。全参 SFT 直接独立加载两份。
- 两者不得共享可变参数存储；参考参数不进入优化器，参考策略在训练期间不更新。`ref_model` 显式交给训练器；不依赖“关闭 LoRA 就得到参考策略”的默认分支，也不同时传入一个已加载 adapter 和另一份新 PEFT 配置。
- 模型文件/基座声明/协议不一致均失败；DPO 本地路径只加载现有本地或本地缓存的精确基座，缺失时不联网补齐，不默默切换全参或另一套参考策略。资源不足时报告错误，不改变算法起点。

首版选择两个独立模型，而不是共享基座切换双 adapter 或预计算 reference log-prob，理由是来源、冻结和保存行为更容易审计，且不依赖不同训练库版本的隐式 adapter 选择。代价是额外显存；这里不承诺任何卡型或模型规模必然可训练。

### 6. 训练目标、资源与产物

采用显式 sigmoid DPO，固定参考策略，不增加损失选择器。根据实际训练库能力检查所有显式配置字段；不支持时明确报错，不静默丢参，不升级或降级依赖来绕过。

训练前审计每行原始来源、完整 messages、当前单条 assistant 目标、协议、两侧实际模板渲染后的 token 前缀及长度。数据落盘使用消息而不是固定 token；DPO 是离线偏好训练，不伪装成 GRPO 的 on-policy token 重放。prompt 与历史/环境消息不参与两侧 completion log-prob；模板边界不能改变已有上下文，chosen/rejected 不得包含环境反馈。任何超长样本明确失败，不能让训练器截掉前缀或决策再声称严格匹配。支持 `--inspect-only` 完成审计而不加载策略权重或训练。

资源策略复用 `TrainingContext`、精度、QLoRA 与日志公共模块。单进程保持单 GPU 防护，DDP 每 rank 独立绑定设备、各自持有 policy/reference；记录全局偏好对批量，不复用 SFT 的 token loss 归一化或 GRPO 的生成组约束。同步保存与主进程写入/验证沿用当前机制；验证失败向其他 rank 广播，不挂起等待。

最终产物为 `dpo_qlora` 或 `dpo_full`，绑定 SFT 起点、冻结参考来源、数据包、协议、请求/有效配置、依赖、分布式资源、请求/实际步数和停止原因。仅导出策略权重，不混入参考 adapter；适配器可独立由明确基座加载。默认位置为 `outputs/dpo/final`，不改写 SFT 或既有研究输出。GRPO 仅在显式指定这个产物时消费它；当前 SFT/GRPO 可接受类型与检查不回退。

### 7. 默认值与旧配置兼容

以下是本次新 DPO 的设计默认，不代表完整历史配方复现：

| 类别 | 默认与依据 |
| --- | --- |
| 生成起点/输出 | `outputs/sft_qlora/final`；`data/dpo/dpo_react_messages_v3_train.jsonl`，避免覆盖旧 `dpo_train.jsonl`。 |
| 采样 | 每任务 5 条、温度 0.8、seed 42、奖励差严格大于 0.05、任务产出率低于 0.25 报警；前四项沿用旧生成器显式默认。 |
| 预算 | 6 轮含 FINISH、每轮最多 256 个新 token；与当前完整多轮入口对齐，不沿用旧 4 轮。 |
| 算法 | epochs 3、lr `5e-6`、beta 0.1；沿用旧训练器显式值，loss 固定 sigmoid，关闭参考同步与额外混合损失。 |
| 资源 | QLoRA 开启、每卡 batch 1、grad_accum 8、max_length 4096；使用当前精度、checkpointing 和 QLoRA 优化器约定，明确区别于旧 batch 2 双全参模型。输入 adapter 保留其既有配置，不重设 rank。 |
| 验证 | 默认开启，平均奖励下限 -0.3；该值来自旧 DPO 验证默认，仅为最低阈值，不是提升保证。 |

`resources/mainline.json` 新增 `dpo` 节，既有 `sft`、`grpo` 和原 `source_baseline` 原值保留；DPO 的新基线来源在本阶段记录，不篡改历史 SFT/GRPO 基线。`schema_version=1` 允许可选 `dpo` 顶层节，旧用户配置缺少该节时只在内存中补包内 DPO 默认并记录来源，绝不写回文件；若显式提供 DPO 节则必须字段完整、类型正确，未知字段仍拒绝。CLI 参数仍优先于配置。

配置资源整体哈希必然变化，更新 `tests/test_config_resources.py` 与 `scripts/check_installation.py` 的当前哈希，同时新增/调整 SFT/GRPO 子树内容一致的检查；不能仅更新哈希就宣称旧默认保全。

### 8. 阶段验证与成功状态分开

在 `StageVerifier` 增加 DPO 阶段，复用现有多轮评测服务、初始化和只读评分，不写独立首步检查器。数据层仍不导入评测层。DPO 使用已声明的现有 Canary 冒烟任务，固定并记录选择、生成次数、温度、轮数与评分配置；报告明确这些任务仅是冒烟质量门，不是独立留出集提升证据。

报告包含 mean_reward、严格 task_completion_rate、parse_rate、false_finish_rate、termination_counts、任务/episode 数、实际执行范围与来源/执行协议关系。虚假完成来自同一次轨迹评分；在共同聚合器补该统计时保留 SFT/GRPO 原阈值和指标语义，不追加新的通过门槛。

保存模型与 manifest 后验证，必要时先释放训练 policy/reference 占用再按产物契约加载验证模型。通过既有主进程边界执行；阈值未达或执行失败时保留模型和失败报告，返回非零，其他 rank 收到失败；显式 `--no-verify` 记录 skipped，不能表示通过。GRPO 的显式 `--model` 不新增强制“必须有 PASS 验证报告”的门槛，与当前 SFT 交接一致；用户可检查失败产物，但不能自动串接继续训练。

### 9. 验证证据边界

工程检查覆盖命令/配置、分层与安装、纯配对与来源审计、冻结参考接线、writer 边界、报告格式及 SFT/GRPO 回归。复用当前测试输入和仓库已有记录；删除前 DPO 测试只作算法历史参考，不重新激活已归档行为基线，不扩充合成模型响应、token、轨迹或研究数据。

已有输入不足以动态覆盖的部分以源码/结构检查和明确的未验证列表交付，不能伪装成真实运行；尤其是实际 tokenizer 边界、参考权重在优化后的不变性、GPU/DDP 训练、显存容量和模型收益。实现引入的现有可运行检查失败仍必须修复。阶段验证功能是后续真实训练时的默认行为，不等于本次工程验收要执行模型评测。

## Risks / Trade-offs

- 严格完整前缀匹配会减少第二轮以后的偏好对，历史 Thought 一字不同也不能合并 -> 保留严格条件、披露任务/轮次产出，不借增加合成数据或共享前缀分支扩大本次范围。
- 完整轨迹分数会受后续采样影响，且同动作不同 Thought 的当前轮被排除 -> 明确这是动作分歧的弱偏好排序，不宣称局部因果归因，不扩大到 Thought 风格偏好。
- 两份模型增加显存，尤其全参路径 -> 记录实际资源并明确失败；更节省显存的双 adapter/参考缓存作为后续独立优化。
- 训练库可能自行截断、套模板或改变 PEFT 参考行为 -> 显式参考模型、实际 token 边界审计、严格能力检查；不把库默认当作规格保证。
- 抽取 GRPO 加载或增加配置节可能破坏已有路径 -> 最小共享抽取，保留 SFT/GRPO 接口和子树值，运行既有保护、配置与安装检查。
- 目前缺少训练栈和真实研究资产 -> 规划并实现失败保护，工程报告分开列出已检查/未验证，不为验收安装模型或制造证据。

## Migration Plan

1. 先增加兼容配置、纯产物契约与数据配对边界，确认原 SFT/GRPO 默认与现有检查保持。
2. 增加数据生成及审计能力，再接入 DPO 训练、参考策略和完整阶段验证，最后开放 GRPO 的显式 DPO 产物输入。
3. 更新统一帮助、安装检查、三语 README 与活动文档，删除其中“DPO 当前仍退出”的表述；历史归档、旧命令字符串和实验记录保持原样。
4. 对已有用户无自动迁移、无重训练要求。未来显式运行新生成入口才产生新数据包；旧协议数据/模型保持旧身份，不能直接继续训练。
5. 回退时撤销本次代码与新入口，直接 SFT -> GRPO 仍可使用；保留用户已产生的 DPO 数据/模型/报告，不通过删除研究产物回退。
