# Proposal

## Why

项目已经具备 SFT、可选 DPO、GRPO 和单机 DDP 入口，但服务器上的环境、启动参数、日志和中断处理仍需分别管理，六组实验容易出现来源不清、配置漂移和重复训练。需要在不改变研究算法的前提下，以固定容器环境和轻量命令统一管理运行，并补齐三阶段完整断点恢复。

## What Changes

- 提供固定代码、完整依赖和镜像摘要的训练镜像与 Compose 配置；保留现有虚拟环境、模型和研究产物，不在启动训练时安装依赖或自动下载输入。
- 在现有 `agentic-arxiv` 命令族新增服务器本地的 `experiment` 管理入口，覆盖预检、后台启动、列表、状态、日志、安全停止、显式强制停止、断点恢复和手动评测；控制端不要求安装训练栈。
- 分离服务器配置、实验配方和本次运行覆盖项，提供 M0、M1、M2、M3、M4、C1 六组配方。通过明确的输入路径或运行编号复用已有合格产物，不自动寻找“最新模型”或执行前置阶段。
- 区分实验组、运行和执行尝试；保存最终配置、镜像、输入指纹、GPU、退出原因、checkpoint 与验证结果，恢复不覆盖旧证据。
- 补齐 SFT、DPO、GRPO 的完整训练状态保存和恢复。第一版限定相同镜像、输入、训练配置、卡数与预算，恢复消耗原预算，不将加载权重重新训练伪装成续训。
- 默认在可恢复的安全边界协调保存并停止；强制停止必须显式选择，不自动升级，不保证保存未完成进度。保留正常训练结束后的既有阶段验证，正式留出集评测仍手动触发。
- 分开记录仓库工程验证与真实单卡/四卡恢复验证，未执行的检查不得声明通过。

### Non-goals

- 不实现自动排队、自动 GPU 调度、自动阶段流水线、自动重试或自动恢复。
- 不实现本机远程控制、SSH 连接管理、管理网页、常驻管理服务或多机训练。
- 不改变奖励、损失、训练切分、模型交接和训练库参数委托语义，不新增奖励消融。
- 不自动生成 DPO 偏好数据、GRPO 探针或信号子集；这些继续使用已有显式入口。
- 不自动授权 docker 组、安装 GPU 运行时、迁移系统存储、重启服务或操作其他用户任务。
- 不在本地实现与工程验证阶段操作服务器或启动真实训练；部署与真实恢复验证须独立授权。

## Capabilities

### New Capabilities

- `experiment-management`: 固定容器环境、服务器端轻量管理命令、六组实验配方、输入引用、运行/尝试记录、状态和手动评测。

### Modified Capabilities

- `training-mainline`: 扩展统一命令入口，并增加三阶段完整 checkpoint、严格恢复兼容性、训练保护状态恢复及分布式安全停止契约。

## Impact

- 涉及 `src/agentic_arxiv/cli/`、新的实验管理模块、`training/sft.py`、`training/dpo.py`、`training/grpo.py`、回调/保护器、分布式控制和来源记录；复用现有训练、评测与数据审计实现，不另建训练器。
- 新增容器构建、依赖锁定、Compose、服务器配置和实验配方资源，以及部署、操作和恢复验证文档。训练镜像以服务器已验证的 Python 3.10、PyTorch 2.10.0+cu126、Transformers 4.57.6、TRL 0.29.1、PEFT 0.17.1、bitsandbytes 0.45.5、Accelerate 1.11.0 为起始基线，完整依赖闭包与镜像仍需独立验证。
- 目标部署为现有单机四卡 NVIDIA 服务器；Docker 权限、NVIDIA Container Toolkit 和镜像存储位置须另行核验，历史检查记录不代表当前状态。
- 现有训练命令及默认参数保持兼容；保存周期等管理配方覆盖项必须显式记录。已有产物只读引用，不升级旧 manifest，不承诺旧 checkpoint 具备新恢复契约。
- 后续服务器部署和真实训练验证须取得独立授权；规划确认、本地实现和工程检查均不构成服务器操作授权。
