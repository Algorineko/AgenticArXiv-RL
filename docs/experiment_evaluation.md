# 独立评测、日志与成本

实验管理只在服务器本地委托一个明确作业，不执行 SSH，不自动完成前置训练。本地工程回归不代表真实模型评测或单卡/四卡恢复已经通过。

## 手动评测

`agentic-arxiv experiment evaluate MODEL --kind benchmark --evaluation-config CONFIG --profile PROFILE --gpus IDS` 为默认的独立 benchmark。`MODEL` 必须是明确本地 Base 或已合格最终产物。配置沿用现有 `evaluate run` 的字段，例如 `repeat`、`task_set`、`split`、`offline`、`snapshot`、`seed`，管理层固定本地模型与独立输出，禁止用 API 模型替换。配置不得含训练参数或阶段验证参数。M0 只执行此作业，不运行训练、数据生成或筛选。

受管容器固定禁网，因此 benchmark 配置必须明确设置 `offline: true` 和已有快照 `snapshot`（M0 也可由明确的配方快照输入绑定）。空配置、联网模式或遗漏快照在规划阶段拒绝，不创建运行记录或申请 GPU；不沿用工作目录中的默认快照。快照须为可解析的非空工具记录 JSON，每条缓存记录包含 `result`，路径及内容指纹冻结为只读输入。结构检查不代表覆盖所有评测任务，缺失的回放记录仍会明确失败，不联网补齐。原有非受管 `evaluate run` 的联网行为不变。

`--kind stage` 只重试 SFT、DPO 或 GRPO 最终产物的阶段验证。其配置接受 `num_samples`（仅 SFT）、`max_iterations`、三个既有质量阈值、`offline` 与 `snapshot`。不会重新执行训练，也不会改写模型目录中的旧验证报告。每次命令创建新评测运行和评测记录，并在对应尝试 `output/verification_report.json` 保存新报告。成功重验的资格须通过准确的 `verification_ref` 显式引用，不自动选最新报告。

正式 benchmark 不自动随训练完成运行，不将留出集结果回流至训练任务池或信号筛选。独立结果的 `source` 固定模型/基座指纹、来源引用与评测输入指纹；容器开始执行前再核对，变化直接失败。`configuration` 保存该次评测配置。Base 不伪称通过训练阶段验证；benchmark 的完整执行不表示模型优于其他模型。

`--diagnostic` 是显式诊断例外：可评测尚未通过验证、但模型阶段/协议/来源契约完整的产物；不跳过模型审计。结果标记 `diagnostic=true`、`qualification_eligible=false`，不得作为合格阶段证据登记或进入正式后续实验。

## 取消与状态

默认停止请求只在完整 episode 之间检查。已开始的模型调用或工具调用没有返回时仍在等待，不能承诺立即释放 GPU，也不会超时自动强杀。中途取消记录 `execution=interrupted`、`passed=false` 和已完成 episode 数；已完成的部分不得作为整套评测通过。评测没有训练 checkpoint，不提供评测内部恢复；重试从新记录开始。

训练已完成而阶段验证失败或中断时，训练预算完成与验证结果分别保留。阶段重试不能增加训练预算。强制终止也不产生评测恢复点。

## 日志与 TensorBoard

每个尝试保留自己的 `logs`、`output` 与控制文件。日志入口读取主进程或明确 rank；读取不启动、恢复或重试训练。TensorBoard 事件清单同时递归扫描当前尝试的 `logs`（受管 SFT/DPO）与 `output`（GRPO 和历史布局），只收录文件，按完整路径去重并排序；不同目录下的同名事件不会互相覆盖。可用原有本地 TensorBoard 工具读取，不新增管理网页或第三方服务。未安装 `[logging]` 时仍能列出事件文件，指标保持未知；显式读取标量时同样使用这份完整清单，不会为了查看状态安装依赖。

## 成本口径

GPU-hours 定义为分配的 GPU 数量乘以墙钟秒数再除以 3600，不是利用率加权估算。训练、阶段验证、独立评测分别汇总；整个尝试的分配成本另报 `allocated_attempt_gpu_hours`。没有阶段计时证据时，纯训练或阶段验证成本保持 `null`，不将整个容器时长误当纯训练时长。

容器启动时间取自启动后的身份核验，状态查询再次同步真实 `StartedAt`，以修正旧记录。Docker 的零时间、缺失或无效时间不参与成本计算，也不以管理命令执行时间冒充容器启动时间；没有有效起止证据时，尝试分配成本保持未知。

各尝试保留恢复起点、实际步数与已提交 checkpoint 步数，物理执行更新次数相加，逻辑训练进度取已提交边界，不把恢复重算当新逻辑进度。未提交工作和重算成本不删除。缺失的耗时、生成 token、峰值显存和历史成本一律为未知，不伪造为零。

M4 复用的偏好生成和 DPO 成本仍单列在上游成本中，不因复用消失。C1 对照成本按已知项与未知项展示，管理器不搜索预算，也不自动宣称严格等预算。
