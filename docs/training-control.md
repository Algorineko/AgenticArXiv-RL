# 受管训练停止协议

本页描述工程实现，不代表真实单卡或四卡训练恢复已经通过。服务器操作、真实模型训练与 GPU 故障注入均须另行授权。

## 请求与状态

每个执行尝试有独立 `control/`。管理端调用纯标准库的 `training.control.request_stop(control_dir, run_id, attempt_id)`，在短文件锁内原子写入 `stop-request.json`。重复请求返回原 `request_id`，不会重复建立保存任务。请求包含 `schema_version=1`、`run_id`、`attempt_id` 和 `request_id`。身份不同的历史请求不会在恢复尝试生效。

训练端写入 `control/stop-status.json`，带相同运行/尝试身份、请求编号、逻辑优化步数、原因与 checkpoint 路径。状态含义：

- `checkpoint_pending`：已在公共优化步边界接受请求，仍未确认保存完成。
- `user_safe_stop`：训练回调已经确认当前步完整 checkpoint 提交，准备退出。
- `superseded`：实际保护停止、预算完成或其他停止原因优先于用户请求。
- `failed`：训练、保存或通信异常，不再声明用户安全停止。

`user_safe_stop` 只是训练侧证据。管理端还必须核验目标容器身份与实际退出，才能展示安全停止成功。请求文件存在、进程退出码为零、普通权重文件存在均不能单独证明安全停止。

## 优化步与保存边界

`ManagedStopCallback` 只在 Trainer 的 `on_step_end` 读取并传播请求。梯度累积微批次、独立 rollout 的工具轮次和后端等待中均不加入控制通信。各 rank 到达同一完整优化步后，主 rank 读取请求并向其余 rank 传播决定。

接受请求只设置 `should_save`，不会提前让某个 rank 退出。标准 `_save_checkpoint` 经受管适配器完成临时目录写入、各 rank 状态确认和最终事务提交后，才进入 `on_save`。停止回调通过适配器提供的当前步提交凭据确认保存，随后设置 `should_training_stop`。三阶段入口必须检查 `user_stopped`，跳过成功 `final` 导出与正常完成验证。checkpoint 保存失败直接抛出，不确认停止，不删除之前有效恢复点。

保护器在日志回调中可能晚于请求检查触发，因此 `on_save` 会再次检查保护原因。优先级为实际异常、实际保护停止、已经完成的原预算、用户安全停止。原预算已经耗尽不能被标成仍有剩余预算的用户停止。

## 故障与强制中断

训练异常处理调用 `mark_failed`，它仅在主 rank 尝试写本地诊断，绝不启动新的 collective。已失败的停止回调不再读取或通信。CUDA/NCCL 或进程故障后不能为了补存断点重新发起不安全的 rank 协调；最后一次完整 checkpoint 保持为候选恢复来源，仍须逐项重新校验。

默认安全停止没有超时自动升级行为。长生成、工具调用或未返回的通信会使请求继续等待，不保证固定响应时间。只有明确选择强制停止并核验容器身份后才终止目标尝试。强制中断不承诺保存最新进度，也不能将未完成目录标成恢复点。

恢复使用新 attempt、新控制目录和新输出目录。恢复精确 checkpoint，而不是重新发放训练预算。历史停止请求不承接，但零方差保护与 Canary 的累计状态必须承接；已经触发保护的 checkpoint 不能通过普通恢复清零耐心。

## Canary 附加状态

`CanaryCallback.state_dict()` 保存版本、监控/采样配置、连续异常计数、触发标志、上次实际监测优化步和完整结果历史。`load_state_dict()` 在后续回调前恢复；拒绝版本不符、配置漂移、损坏计数和已触发保护状态。同一恢复边界的重复日志不重复消耗耐心，已累计两次异常的三次耐心保护仍在下一次异常触发。

## 验证范围

`tests/test_training_control.py` 覆盖并发幂等请求、attempt 隔离、微批次不通信、保存前不退出、优先级竞态、缺失提交确认、通信异常后不再 collective、后续异常撤销停止确认和非主 rank 不覆盖状态。其中四进程 CPU/Gloo 用例以控制元数据检查不同本地轮次/耗时、相同公共优化边界与错误传播，不加载模型或执行训练。`tests/test_canary.py` 覆盖累计耐心、历史往返和保护恢复拒绝。这些是无模型工程验证，不代替连续训练与安全停止恢复的真实单卡/四卡对照，也不证明 NCCL 故障时所有真实后端的退出时限。
