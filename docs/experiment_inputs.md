# 实验配方、只读登记与共同来源

配方资源位于正常安装包的 `agentic_arxiv/resources/experiments/recipes/`，包含 M0、M1、M2、M3、M4、C1。服务器模板位于同目录下的 `profiles/server.json`。这些是需要人工填写的模板，不是已通过预检的正式实验，不包含冒烟产物、可疑镜像摘要或默认研究预算。可以通过 Python 标准库 `importlib.resources.files("agentic_arxiv")` 定位并复制到显式工作区，不能修改已安装资源作为运行记录。

| 配方 | 本次唯一作业 | 必须人工提供的模型来源 |
| --- | --- | --- |
| M0 | 独立 benchmark，不训练 | 本地完整 Base |
| M1 | SFT | 本地完整 Base，或通过独立登记复用已有合格 SFT |
| M2 | DPO，不生成偏好 | 明确共同 SFT，已有合格偏好包 |
| M3 | GRPO | 明确共同 SFT |
| M4 | GRPO，不执行 DPO | 明确 DPO 及其共同 SFT |
| C1 | 预先确定更长总预算的 GRPO | 与 M3 相同共同 SFT，明确 M4 比较口径 |

M1 的登记不执行 SFT，选择 M2/M3/M4/C1 也不自动执行任何前置阶段。M4 必须人工准备并明确选定 DPO，不能退回 SFT。六配方不能当作一条自动流水线使用。

M4 可通过 `inputs.model` 或 `inputs.source_dpo` 指定 DPO；同时提供时，两者解析后必须是同一产物路径，否则在容器预检和创建运行之前拒绝。相对路径、绝对路径或登记引用可以不同，但不能让预检与训练各自选择不同模型。

## 人工准备与预检

1. 复制服务器模板并填写真实工作区、管理根、允许输入根、缓存根、普通用户 UID/GID、明确 GPU 范围，以及已独立核验的 `image@sha256:...`。`null` 或未核验摘要不能作为正式身份。
2. 复制一个配方，填写所有使用的真实输入。`training_config: null` 仅表示使用包内唯一主线默认配置，不会补齐模型、数据、快照或预算。训练预算必须在启动前明确选择步数或 epoch，不能同时填写。M0 不训练，其预算字段保持 `null`，`checkpoint` 也必须为 `null`；其他配方显式设置周期保存，SFT/DPO 默认模板为 50 步，GRPO 为 10 步。
3. 人工复用已有合格 SFT；M2、M3、M4、C1 的 `source_sft` 都应指向同一个登记 ID。登记 ID 来自实际登记结果，`REPLACE_WITH_...` 只是必须替换的占位符。M4 的 `model` 则指向实际 DPO 登记，DPO manifest 必须准确追溯相同 SFT 的模型及 manifest 指纹。
4. 对 M3、M4、C1 填写同一训练任务池与筛选政策的明确文件路径及 SHA256。不能因模型起点不同而暗中重筛选。所需偏好、探针或信号子集须用既有显式准备入口另行准备，本管理器不会生成。
5. 填写固定正式评测配置。训练成功不自动触发 benchmark；评测输入不能反馈到训练筛选。先执行只读预检，解决全部缺失项后再另行授权启动。

## 训练预算与恢复

六份模板均显式列出 `budget.max_steps: null` 和 `budget.epochs: null`，表示尚未确定预算，不是无限训练或自动使用默认预算。训练只能选择一种模式：

- 步数模式：`budget.max_steps` 为正整数，`budget.epochs` 为 `null`；生效训练配置的 `defaults.max_steps` 必须等于声明值。旧步数配方可以省略新增的 `epochs` 字段。
- Epoch 模式：`budget.max_steps` 为 `null`，`budget.epochs` 为正整数；生效训练配置必须设置 `defaults.max_steps: -1`，且 `defaults.epochs` 等于声明值。可在 `training_overrides.defaults` 中明确填写，两项不会由管理器自动换算或修改。小数、布尔值、零和负 epoch 不是有效预算。

受管恢复继续原先同一总预算和数据消费位置，不将声明的总 epoch 再完整执行一遍，不因恢复将步数与 epoch 模式互换。C1 也可预先声明 epoch 预算，但更多 epoch 不等于更多固定 GPU-hours，更不构成与 M4 严格等预算的证据；仍需明确 M4 对照、共同 SFT、任务池、筛选政策及成本口径。未获得真实训练授权时只验证配置、来源与恢复接线，不据此宣称真实 epoch 恢复已经通过。

## 精确引用合同

路径既可写字符串，也可写对象；相对路径按显式工作区解析。受管模型只接受以下三种明确引用，没有“最新”规则：

```json
{"kind": "path", "path": "/absolute/existing-model/final"}
```

```json
{"kind": "registration", "registration_id": "artifact-实际登记标识"}
```

```json
{"kind": "run", "run_id": "run-实际标识", "attempt_id": "attempt-实际标识", "artifact": "final"}
```

受管 run 引用必须明确到某次尝试，不能通过 `current_attempt` 猜选模型。checkpoint 不属于最终模型引用，应走显式恢复入口，且最终模型登记绝不授予完整训练恢复资格。数据、快照、切分及政策文件只接受明确路径。

管理端复用现有产物校验：阶段、当前协议、实际必要权重文件、adapter 基座声明、可核对本地基座与输入指纹。它不加载模型、不初始化训练器，不会在离线输入缺失时下载补齐。需要 tokenizer 的实际模型审计属于独立预检，不把纯元数据检查当成训练或真实恢复验证。

模型来源类型与本次 `defaults.qlora` 是两个独立维度。M2、M3、M4、C1 按已核验的 `metadata.stage` 绑定加载参数：`sft_qlora`/`dpo_qlora` 输入使用声明的 adapter 基座，`sft_full`/`dpo_full` 输入保持执行 `base_model: null`，不会把溯源基座误传成 adapter 专用覆盖。全参输入的原基座身份和只读挂载仍保留；旧训练配置或独立输入字段中的 `base_model` 不会重新覆盖这一加载合同。adapter 的显式基座仍经既有本地内容一致性校验，不能通过归一化掩盖冲突；独立输入仍优先于旧训练配置。预检、新尝试和恢复重渲染共用同一规则，M1 的显式 Base 输入审计及只读挂载不变，不改非受管训练入口。

M2 除明确的 `data` 和 `data_manifest` 外，还按偏好包 manifest 的固定合同解析 `source_model_manifest`、`split_file`、`files.traces` 与 `report`。相对路径以 manifest 所在目录为基准，绝对路径保持原值；每个文件均核对声明的 SHA256，`files.data` 必须与配方数据相同。结果保存为 `data_manifest.runtime_dependencies` 的明确文件身份清单，不递归收集评分源码、历史配置等来源记录，也不改为挂载整个偏好包目录。依赖同样必须通过输入根白名单、禁止符号链接及路径别名、与可写目录隔离等检查。

无 GPU 预检和正式训练复用同一最小只读依赖清单；清单进入不可变尝试身份，正式训练在加载模型前重新核对依赖文件内容。文件挂载齐全、路径及指纹检查通过只证明运行依赖可定位，不代表偏好包内容、真实 tokenizer 或 token 边界审计已通过；这些仍由容器内既有 DPO 只读审计独立验证。

## 只读登记及资格

登记只在 `registrations/<artifact-id>/reference.json` 新建引用记录，原产物目录、manifest、权重及其路径不改变，不升级旧格式，不把历史训练伪称为本次执行。登记记录保存模型、基座和阶段验证报告的身份，并明确 `registration_only: true`、`resume_eligible: false`、历史执行未知。

登记允许保留历史验证未知项，但未知、跳过、失败或被中断的阶段验证不会提升为正式后续实验输入。通过报告必须匹配本次模型的阶段、准确模型路径和训练协议；复制其他模型的 `passed: true` 报告不构成资格。重试阶段验证使用独立评测记录，不重新训练。

重验成功后可在明确模型引用上添加 `verification_ref: {"run_id": "实际评测运行", "attempt_id": "实际评测尝试"}`；登记时也可通过 `--metadata` 指定的 JSON 文件传入相同 `verification_ref`。只接受完整通过的非诊断 `kind=stage` 结果，核对模型/基座指纹、原定评测配置及报告的模型、阶段和训练协议。不会搜索最新评测，不覆盖旧失败报告；后续引用仍复查已选证据的文件哈希。诊断评测不能提升输入资格。

每次使用登记都重新核对旧记录与当前文件。模型、基座或验证报告变化即拒绝，不重新登记同一引用、不更新旧指纹来掩盖差异。受管 run 的 final 同样要求提交时保存的身份。迁移导致绝对来源路径失效时应人工解释和准备，不修改旧 manifest 或悄悄把另一模型当作同一来源。

## M4 与 C1 成本口径

`budget.accounting` 使用 `gpu_hours`，报告含义是分配卡数乘实际占用时长，不是 FLOPs 或有效利用率。`budget.costs` 分别记录 `preference_generation_gpu_hours`、`dpo_gpu_hours`、`grpo_gpu_hours`，未知项保留 `null`，不是零。共享 SFT 可以只训练一次，但 M4 的偏好生成与 DPO 成本不能因复用已有产物而消失。

`comparison_group: "M4"` 只是 C1 的比较意图，不能替代明确对照来源、实际成本证据或预算预声明。C1 必须填写 `comparison_reference`，可使用明确声明 `group: "M4"` 的配方/成本报告路径，或准确 M4 运行及尝试引用。引用对照不要求该 M4 已有 final，不额外引入实验先后顺序；配置/报告中已声明的共同 SFT、任务池和政策须与 C1 一致。成本摘要保留已知分项之和与未知分项；任何必要分项未知时总成本保持未知。管理器不会预算搜索、自动估算历史成本、延长已完成 M3 来冒充 C1，或自动标注“严格等预算”。

## 验证边界

工程回归只构造临时目录及控制元数据，复用既有必要文件存在性替身，不产生模型参数、研究响应、偏好或训练轨迹。配方解析、路径解析、哈希不变、来源不一致拒绝与未知成本检查通过，不代表镜像已构建、服务器已部署、模型有效或单卡/四卡真实恢复已验证；后者必须独立授权并留下真实证据。
