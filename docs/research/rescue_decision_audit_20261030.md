# 研究救援决策审计（2026-10-30）

## 决策

**可救回为审计型负结果/复现报告；原方法贡献目前救不回；不应强制转向 RSI。**

这里的“可救回”限于诚实呈现可复验材料、协议修正和失败证据，不代表当前草稿已经达到投稿标准。现有实验不足以支持新的学习算法、一般性“SFT损害组合泛化”定律、模型规模因果结论、RSI 或 agent–environment co-evolution 主张。

## 支持这一判断的关键证据

1. 一条短 SFT 臂在 12 题开发探针上从基座 8/12 到 12/12，但两条 16-step SFT 臂在已用过的 24 题流程评测上均为 0/24；剔除四条提示契约冲突任务后仍为 0/20 对 9/20。它证明这个开发门槛没有挡住该配方的回归，不证明健康训练的 SFT 普遍造成回归。
2. 训练、开发和最终池只按目标论文 ID 分开，操作家族和模板有交叠；且事后发现训练出现过的双操作链也有失败。故“新组合导致失败”或严格的组合外泛化都不能作为结果。
3. BFCL 32 题 native 执行可复算，7B 为 9/32、1.5B 为 2/32；但 22/32 首轮文本与先前 BFCL v3 源池精确重合。模型身份、大小、调用预算使用量也不同。它适合做跨版本协议/执行器校准与容量描述，不是独立泛化或规模因果结果。
4. 相关工作已直接覆盖环境共同进化、组合覆盖/可见证据监督、工具扰动恢复、失败纠错和错误传播。把现有错误恢复后验分析升级成独立新基准/算法，缺乏 novelty 支持。
5. 冻结 final 已被使用，历史快照和历史训练 JSONL 找不到；再跑同源任务、增加 seed 或追加 SFT 步数都无法恢复独立验证，也会弱化现有冻结协议的可信度。

## 当前草稿的真实状态

现有英文稿已有摘要、背景、实验记录、结果、限制和决策门槛，是可用的内部完整草案，但**不是可直接投稿的稿件**。还需针对目标 venue 完成正式引用/参考文献、图表、实现与环境细节、逐项主张—工件对应表及编辑性压缩；且需要处理单次 final、小样本/家族重叠、提示冲突、结果混合不同任务/后端等限制。缺这些工作不会改变当前科学结论，只影响表达与可复验入口。

摘要中曾用“target-disjoint task pools”，可能误导读者认为任务谱系也隔离。已改为精确说明“目标论文 ID 不同、操作家族重叠”，并在实验记录中列明这一限制。

## 资源和继续门槛

本轮 A40 GPU1 尚有显存，但有活跃计算任务；显存空闲量不代表可独占。当前没有一个符合已冻结协议、又能新增辨识度的 GPU 实验，因此不启动推理/训练。没有继续算力也不构成阻塞：目前主要剩稿件完整性工作。

如果要把项目升级为方法论文，必须另立新实验，而非给本稿追加补丁。至少需要：

- 先完成对最接近工作的差异表，确认具体未解缺口；
- 使用不同的任务源/接口或明确隔离的任务生成机制，按任务血缘拆分训练、验证、最终集；
- 设定健康且非地板/非饱和的模型和原生工具基线；
- 前瞻冻结候选诊断/干预及简单多步回归对照，并以独立验证结果决定是否启用 final；
- 只有候选方法在这类控制下稳定胜出，才值得讨论 RSI 是否提供额外收益。

若目标是完成当前项目，继续写作并报告为失败审计是合理路径；若目标必须是有新方法的主会论文，则当前主张应判为救不回，换题或另立研究问题比继续向现有实验投入 GPU 更合算。
