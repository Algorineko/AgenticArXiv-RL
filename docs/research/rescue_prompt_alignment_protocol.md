# 训练/运行提示对齐诊断（推理前冻结）

代码证据：当前generate_deterministic_trajectories真实执行setup，却在调用build_sft_samples_from_history时只传任务和本轮历史；该函数没有setup可见状态参数。BenchmarkRunner会在相同ReAct模板的history前加入build_visible_setup_context。历史训练JSONL不在现仓，不能据源码直接认定发布权重的训练输入；先把这一差异作为可检验假设。

在receipt_catalog_v1开发12题上比较三个固定呈现：baseline；current_actions_only（保留真实setup状态及本轮动作历史，只不呈现setup文字，复刻当前SFT生成器的输入结构）；state_facts_only（保留状态所有事实，仅去掉“以上是已存在的会话状态，不属于当前任务动作，请勿重复执行。”）。两个诊断都不读取gold，不添加动作指令，不修改工具/模型/预算。current_actions_only会丢失生产所需上下文，只用于诊断，不能直接替换产品默认行为。

每模型本机/A40 GPU1分别跑三臂，合计72轨迹；greedy seed45、384新token、6轮、每臂900秒。主指标操作凭据＋FINISH，次指标strict、首步FINISH与每对状态变化。预先预测：若是状态文本而非底层缓存使GRPO提前停止，隐藏setup将使原先“已下载”翻译的3个首步FINISH减少；若只有去掉禁止重复句就有效，则具体命令措辞是更窄的解释。零效果同样报告。

最多两个候选，只做这一次；不会据分数改写文本。若某模型任一候选在开发集凭据率正收益且无原成功题退化，才打开已冻结的新promotion12题对该模型做一次baseline/候选配对。若两者均满足，优先总收益更高者，同收益优先保留事实的state_facts_only。这仍是静态接口诊断与工程筛选，不是RSI，也不声称跨任务族泛化。

final保持封存；规则执行器12/12必须并列报告。即便候选通过promotion，也不能仅据这套受规则覆盖的窄任务集升级为论文方法贡献。
