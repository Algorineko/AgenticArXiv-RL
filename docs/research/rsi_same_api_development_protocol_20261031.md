# 条件式同 API 批量接口开发对照（2026-10-31）

冻结于前一轮四题校准完成前。触发条件：前一轮完整4/4结束且成功0/4、原始轨迹与终局回放通过、最终发现文档已生成。其他结果跳过此开发对照，转入后续研究决策，不请求用户介入。

前一轮已完成的训练轨迹中发现一次字段语义混淆：模型将原生业务 API 名写为通用批处理的代理工具名，整批拒绝后提前结束。新增通用的 `batch_api_calls(app_name, api_name, arguments_list)`：固定一个 app/API，提供一组显式具体参数；每项消耗一次原生调用预算。旧 batch_tools 仍存在。结构错误/超预算在执行前拒绝；子调用失败停止且不回滚。SQLite 状态/预算测试和真实 AppWorld 文档调用的串行一致性检查均通过。

本次仅用于开发，非 RSI/正式模型对比。选取原四个冻结 meta_train/inner_train 的前两题（不是结果驱动挑题）。如果前轮后的中性Qwen连接探针返回正确的原生工具调用，选择 `qwen/qwen3.6-27b`；否则继续 `doubao-seed-2.0-mini`。选择规则只依赖预先声明的连接检查，不依赖两题分数；网关别名不证明模型实际权重。

全部实例使用同一接口与固定提示，每题最多24个模型响应、128基础调用尝试，每次响应最多4个顶层工具调用，每批最多16项。总预算：最多50次API尝试（包含重试）、800k input、50k output tokens，单次响应上限2048 tokens，15秒限速。完成后基于冻结的实现源码独立回放并写结果。不得读取 meta_dev/最终任务内容，不得将参考源码/解答提供给模型。

这同时改变批量接口、提示，而且连接检查可触发模型切换；分数变化无法单独归因于任何一个因素。即使1/2成功也只是训练开发可行性信号，下一步仍需更大基线和等预算对照。全部失败时应继续分析工具使用和任务层错误，不把它解释成递归无效。
