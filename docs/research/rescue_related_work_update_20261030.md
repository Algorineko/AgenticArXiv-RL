# 2026-10-30 相关工作补查与可主张边界

本次在实际训练/最终验证完成后重新核查最接近的原始论文页面，避免把新工程发现误称新算法。以下是范围判断，不是复现这些论文的性能结论。

[SEAL: Synergistic Co-Evolution of Agents and Learning Environments](https://arxiv.org/abs/2605.24426)（2026-05-23）已把可验证失败诊断同时用于训练接口演化与策略更新。因此“RL＋Harness/环境共同进化”这个宽主题已有直接前作；仅把当前项目加上自改提示循环不足以形成差异。

[Trajectory2Gym](https://arxiv.org/abs/2610.33568)（2026-10-24）直接讨论组合覆盖与学习者可见证据支撑的监督，并报告多规模、多个真实工具交互基准的实验。它与“修正SFT可见状态＋补组合数据”的路线非常接近；本项目当前证据只能作小模型受控诊断，不能声称首次发现这两个要求。

[OpenAgent](https://arxiv.org/abs/2607.01084)（2026-07-01）已分析SFT/RL面对查询、动作、观察、领域变化的脆弱性并提出扰动增强训练。[Environment Tuning](https://arxiv.org/abs/2510.10197)也已研究静态轨迹过拟合与环境反馈/奖励训练。故“静态训练会退化”“环境比单纯SFT更好”亦不足以作为新主张。

错误恢复这条后续线的可主张空间也明显收窄。[AgentErrorBench / AgentDebug](https://arxiv.org/abs/2509.25370)已提供跨 ALFWorld、GAIA、WebShop 的失败轨迹分类与纠错反馈，并报告迭代恢复收益；[ToolMaze](https://arxiv.org/abs/2606.05806)直接评测工具扰动下的动态重规划与异常恢复，指出隐式语义失败和复杂依赖图会使恢复显著变差；[AgentProp-Bench](https://arxiv.org/abs/2604.16706)则审计工具使用轨迹中的错误传播与运行时拦截。它们与本项目后验观察到的“工具错误后局部继续、但很少完成整轮”高度邻近。因此这条轨迹分析只能保留为本项目的描述性案例，不能包装成新的错误分类框架、恢复基准或恢复算法。

当前新增证据的价值是可审计地改变研究决策：同文/同真实状态下可见历史文字影响发布模型；短配方在原语探针满分却在预先封存的新组合上0/24；静态规则已覆盖窄探针；BFCL派生静态匹配端口与官方后端评测应分清。这些结果排除了若干错误路线，尚未构成超越上述工作的改进方法。

若继续投入方法研究，唯一尚可单独立项检验的方向是：能否在不消耗最终集的前提下，用训练前或开发阶段的诊断预测具体组合回归，并使固定预算的选择优于原语分数、简单静态控制与随机选择？这只是待验证假设，不是当前稿件结果。若做接口/奖励联合优化，SEAL、环境调优与数据覆盖基线应明确纳入，而非只对比退化的公开2epoch SFT。若无新颖且可执行的对照设计，本项目宜止于审计型负结果稿，不应以GPU空闲为由继续加实验。
