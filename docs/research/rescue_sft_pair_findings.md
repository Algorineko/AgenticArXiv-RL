# 新训练配对结果（开发阶段）

两臂均从同一原始1.5B权重初始化，在同一4090物理GPU1训练16个实际optimizer步骤，seed123、相同64个训练决策行/顺序、相同2193个监督token、同样FP32参数/优化器与BF16前向/导出。输入token数hidden132897、visible137110，因为干预增加状态文字，不能称等token。

| 训练输入 | 正常可见状态运行 | 隐藏setup文字运行 |
|---|---:|---:|
| hidden | 12/12 | 12/12 |
| visible | 6/12 | 6/12 |

主指标为实际操作凭据＋FINISH。可见训练臂对隐藏训练臂的六个退化全部是显式force=true下载任务，而六个翻译任务都成功。因此不应把这次差异说成统一的“提前FINISH机制”；至少涉及参数契约学习。交叉部署结果也不支持简单“训练/运行格式对齐即修好”的解释。它只说明在这个固定短配方、决策样本与种子上，新增状态文本改变了所学行为；不能推广为永远隐藏状态更好。

两臂训练用时分别36.921/36.781秒，峰值分配显存约29.5/29.6GiB。训练loss下降、参数哈希变化、16条optimizer记录均已核验；不是零步假臂。没有根据loss选checkpoint或加步数。没有RL或自主搜索。训练数据仅AI论文训练池，与开发LG目标论文分开，原语族/编号模板仍重合；规则执行器在这12题12/12，不能将新模型的12/12叫算法突破。

原始模型在同一开发探针为8/12，公开2epoch SFT为0/12、隐藏运行提示6/12。这强调应先证明健康SFT起点与接口有效，不能把从退化发布权重恢复解释为一般能力创造。新16步臂也只能称短训练可行性产物，尚不称完整健康SFT。

下一步三模型全部在原封存24条CV组合任务上做一次描述性验证；协议cd0cbb6已在最终推理前推送，不据最终分数改训练或提示。最终结果另补，本页不预告泛化成功。
