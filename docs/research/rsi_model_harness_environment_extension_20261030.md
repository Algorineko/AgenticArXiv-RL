# RSI 后续扩展：有限 RL、环境课程与 TTT

用户已授权考虑中间阶段的有限 RL，以及 model、harness、environment 协同演化和 TTT。它们作为可逐项检验的干预加入研究路线；当前执行 P0，不把尚未运行的更新写成效果结论。

## 可验证的统一问题

在固定总资源下，改进器应当把下一个预算块用于模型更新、harness 更新，还是训练环境/课程更新？递归改写这个资源选择程序，是否优于固定选择程序与相同经验的非递归元优化？

状态可记作 `(模型θ, harness h, 训练环境分布 e, 改进程序 m)`。任务验证器、最终测试分布及资源计量器保持外部固定。环境演化改变训练题的难度、组成和反馈方式，不能把最终评分标准改成更容易的标准。最终分数在同一个外部任务分布比较。

## 分阶段启用

1. API＋CPU 阶段：冻结权重，只改 harness 和改进程序；环境课程先固定。先证明接口、评分和非地板/非饱和基线有效，再跑递归对照。
2. 低成本环境课程：允许从预先核验的任务生成机制中选择课程与训练状态；使用固定课程、随机课程、人工难度课程作对照。改变课程和改评分器是不同的操作。
3. 有限 RL：可以先在 CPU 上学习预算/课程选择的 contextual bandit 或小型策略；这属于控制器学习，必须明确它没有更新 LLM。需要 LLM 权重 RL 时，另用可训练的开放权重小模型和单张 A40，预先冻结 rollout、KL、更新步数、训练预算与健康基线。不以一次极短失败训练作为 RL 对照。
4. TTT：真正的 test-time training 涉及可访问的参数或适配器更新。当前 chat API 只证明能推理，不能假定能拿到梯度、logprob 或修改权重。API 内的反思、记忆和提示更新称 test-time adaptation，不称参数 TTT。若引入本地 LoRA/其他可训练适配器，须明确测试时可见数据/反馈，分别设置每题重置与跨题保留；最终参考答案和隐藏检查器标签不进入更新。

阶段 3/4 的 GPU 更新优先 A40，单卡、按当前空闲显存留余量，并记录真实 optimizer steps、权重/适配器哈希、峰值显存与完整训练成本。不能将 API 模型和本地模型的差异归因为某个训练操作；机制对照使用同一基座。

## 必要消融

先做 `h-only`、`e-only`、`θ-only` 与无更新基线，确认各干预可用；然后检验 `h+e`、`θ+h`、`θ+h+e`。调度机制比较固定比例、随机/简单启发式、固定外层元优化和递归自改。总预算包括训练、失败 rollout、环境生成与验证。组件增加后分数上涨不能单独证明协同；协同需要相对于预先声明的组合对照的增量证据。

TTT 另比较不适配、同预算推理搜索、SFT 型适配和 RL 型适配。新任务家族的泛化与已知家族适配分开；“在同一道题上反复训练到过关”不能替代独立测试。

## 前作约束

[Self-Adapting Language Models / SEAL](https://arxiv.org/abs/2506.10943)已经把自生成编辑、参数适配与外层强化学习连接起来；[TTRL](https://arxiv.org/abs/2504.16084)研究测试时强化学习；[End-to-End Test-Time Training for Long Context](https://arxiv.org/abs/2512.23675)研究通过测试时梯度更新学习上下文；[TTT-Discover](https://arxiv.org/abs/2601.16175)研究发现任务中的测试时训练。本次核对原始摘要，不是复现。故“加入 RL/TTT”本身不提供创新；仍需回答受控资源下的递归选择价值。

当前启动不需要额外 GPU 或大模型 API。若进入参数 RL/TTT，再依据可训练模型、实际显存余量和先导结果选择实现；不为凑齐协同演化标签同时启动所有组件。
