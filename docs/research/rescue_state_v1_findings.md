# 请求前状态反事实探针结果

本轮48条模型轨迹全部完成，无框架执行异常。两台机器分别使用物理GPU1，未训练权重。协议在推理前以 `7c60503` 提交推送，未根据结果修改分栏文本。

| 模型/提示 | 严格成功 | 首步FINISH | false_finish | 轮数耗尽 |
|---|---:|---:|---:|---:|
| 原始1.5B/原始呈现 | 4/12 | 0 | 0 | 3 |
| 原始1.5B/状态分栏 | 5/12 | 0 | 2 | 1 |
| SFT+GRPO/原始呈现 | 3/12 | 5 | 5 | 0 |
| SFT+GRPO/状态分栏 | 4/12 | 4 | 4 | 0 |

最清楚的证据来自同文翻译请求的三对反事实：GRPO原始呈现在仅列表状态下3/3正确调用翻译，在请求前已下载状态下3/3直接FINISH，且没有任何本轮工具动作。状态分栏仅修复第1篇，另两篇仍直接结束。这支持“请求前状态影响本轮是否执行”的行为假设；不能据此推断模型内部表示或把责任归因于RL本身。原有状态块本来含有“以上是已存在的会话状态，不属于当前任务动作，请勿重复执行”，本实验没有去掉这句话；具体措辞、活跃引用与下载状态同时随合法setup改变，尚未逐因素解耦。

强制重新下载是另一个失败类型。GRPO两种呈现均0/6严格成功，其中一部分直接结束，其余虽然调用下载却未传force=true。分栏并未补足这个参数契约。离线下载替身不实现真实网络刷新，不能把本项分数叫作实际重新下载成功率。

原始模型分栏修复两条仅列表的强制下载请求，但使原来成功的一条翻译退化，净增1题。该模型两臂都有额外合法工具调用而导致严格失败的轨迹；原始呈现还存在2次工具失败，分栏为0，均不是框架执行异常。因此不能将4/12或5/12解释成真实目标只完成了这么多。

这轮只有两个任务族、三个引用参数、六对请求，不做显著性结论或最优提示选择。两种模型运行于不同硬件和torch版本；只在同一模型、同一机器内比较提示。未评测promotion_val/final_test，未自主生成或选择候选，因此不属于RSI。

## 研究取舍

研究仍值得以“会话状态下的工具控制可靠性”继续推进，尚不足以恢复旧论文的性能结论。已有可复用权重、冻结真实元数据、完整轨迹和可重复失败类型；这比立即扩大训练更有诊断价值。两个简单人工提示都没有稳定解决问题，不能据此推导必须转向RSI。

下一阶段先补充独立的目标操作验证：核查实际观察中的论文身份、翻译任务创建、force参数与结束状态，允许额外有效动作，并明确其仍是离线替身契约。随后再冻结更多会话历史/请求改写，并用相同预算比较静态修复与候选搜索；有可复验收益之后再决定训练或受控RSI。当前不把任何分栏候选晋级，不解封最终集。

原始轨迹和可重算分析在 `artifacts/rescue_state_v1/`；44项相关测试通过，旧四臂分析经代码复用后仍逐字段一致。来源、预算、模型权重、任务覆盖和轨迹哈希由分析器校验。
