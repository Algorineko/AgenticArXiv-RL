# 操作契约与凭据基线（推理前冻结）

问题：状态分栏只带来各1题净增；原始模型严格分还漏记额外有效调用。因此新增静态“请求契约＋本轮操作凭据”呈现，并加入不使用模型的请求规则执行器，检验此任务是否需要学习或自主改进。

候选只从用户文本解析单一编号翻译或显式force=true下载请求；其他请求不干预。目标论文从任务开始时的真实session列表解析；凭据只读取本轮执行观察。不读取gold、task id或预期链。分栏不修改真实工具调用，不拦截FINISH，不绕过模型，也不增加模型调用上限。规则执行器从同一文本编译调用并FINISH；其高分只能表明任务可被规则覆盖，不能作为模型能力。

数据：新目录rescue_receipt_catalog_v1，开发12题保持原样；新promotion12题使用CL论文、第4/5/6篇和预先固定的请求改写，仍为两族六对。train与final完全保留，模型不读final。新promotion不是旧实验的复用结果，不将它冒充真正新语义任务族。

步骤：参考策略/直接结束/规则执行器预检开发集；两模型各在同一机器对比baseline和receipt_contract（本机GPU1原始权重、A40 GPU1发布GRPO）。每臂12题，greedy seed45，384新token，6轮，900秒。唯一候选固定后不再调整；若任一模型开发集operation_and_finish正收益且无原成功题退化，则仅对该模型做一次新promotion配对验证；否则停止该候选，不看promotion模型分。

主指标为匹配目标论文且本轮实际执行所请求操作后FINISH的凭据率；次指标为严格链、operation_seen、工具/解析失败、耗尽、token。翻译凭据只证明创建PENDING任务；force只证明请求参数传true并收到READY替身观察，不证明真实刷新。允许额外有效调用；不要求历史无任何错误。目标论文评测用冻结oracle，凭据解析独立于严格链；这仍不是完整独立端状态验证。

候选是人工固定静态基线，非RSI。规则执行器若解决任务，研究重点应转向更丰富任务与故障机制；不能用同一小套题继续训练刷分。不同模型/机器间不比较耗时，不隔离RL因果效果。不做显著性声明。
