# A40 本地模型 AppWorld 开发诊断协议（2026-10-31）

冻结于开源模型中性工具探针结果出现前。触发条件：已完成并回放的 mini 模型同 API 批量开发检查为0/2；A40 Qwen3-8B 中性探针返回正确原生工具格式，且模型文件指纹、源码和GPU资源检查均通过。否则不启动任务推理。

使用相同两个已暴露的 meta_train/inner_train 开发任务、同一独立 AppWorld 检查器、固定 same-api-batch 接口和提示。模型换为公开 Qwen3-8B，单卡 BF16、greedy、non-thinking；每题最多24个模型响应、128基础调用尝试，整个运行最多50次模型调用、800k输入和50k输出本地分词 token。单次生成1024 tokens，输入上下文最多8192 tokens，超过时单列 `model_context_limit`，不能记成正常 final。mini 对照单次生成上限为2048，因此两者不能作为严格等配置模型优劣比较。

服务器启动前重新选单卡：优先物理1，再0/3/2；至少40,000 MiB空闲、利用率低于10%。模型服务器再次校验已下载文件的大小及SHA256，再次检查显存；通过 `CUDA_VISIBLE_DEVICES` 暴露唯一选中GPU，PyTorch分配器上限60%。每次生成前显存至少还有8 GiB，资源不足单列并终止，进程退出释放显卡。远程服务器最长运行一小时，输入不执行模型生成代码；任务工具仍由本地受限代理执行。处理后的任务提示和工具观察通过SSH私有连接传输；模型无法调用参考源码/检查器，原始轨迹仅在私有缓存。

每个响应记录实际分词器输入/输出、GPU峰值分配/保留、上下文/解析/资源错误及停止原因。环境的源码使用冻结副本回放，且核验模型服务器/客户端源码及模型文件清单摘要。此流程不调用外部LLM API，不运行RL或参数更新。

仅是最多两题的开发可行性检查：模型、上下文和生成上限都与mini运行不同，分数变化不能归因于单一因素；没有新颖性或RSI效果结论。最终集和meta-dev保持封存。GPU不可用、连接失败或指纹核验失败时中止，不能把它们填作模型任务失败。
