# A40 开源模型准备与资源边界（2026-10-31）

目的：API 目录中的 Qwen 路由在两次中性检查中返回502，当前 mini 基线也在开发集处于0成功。为准备可核实参数规模、未来可训练的备选模型，下载官方 [Qwen3-8B](https://www.modelscope.cn/models/Qwen/Qwen3-8B) 并做一次中性原生工具格式检查。此检查不会访问 AppWorld 任务、参考解或最终集，不能据此宣称任务能力或 RSI 增益。

A40 服务器用户目录当时可用约33 GB；使用空闲约333 GiB的临时文件系统 `/tmp/agentic-rsi-qwen3-8b-20261031`，包括 uv cache、模型和日志，避免挤占用户目录。此临时目录不是持久备份。首次测量服务器GPU0/1/3各超过40,000 MiB空闲；实际执行时重新检查，优先物理1号卡，再选择0/3/2中显存至少40,000 MiB且利用率低于10%的单卡，若无合适卡则跳过。

依赖隔离在临时目录：Python 3.10、PyTorch 2.7.1+cu128、Transformers 4.57.6、ModelScope 1.40.2（安装时实际版本）。从ModelScope公开模型库下载，requested revision为 master，完整权重逐文件计算SHA256以固定实际内容；哈希是内容指纹，不宣称已验证上游签名。

中性探针把 `CUDA_VISIBLE_DEVICES` 限于选中物理卡，PyTorch分配器限单卡总显存60%；模型加载前再次核查40,000 MiB空闲，加载后至少保留4 GiB，prompt最多4096 tokens，生成最多256 tokens，BF16，greedy，禁用thinking。记录峰值 allocated/reserved，另外的CUDA上下文开销不计入分配器峰值。若资源不足自动跳过；不使用多卡通信、不启动训练。

训练任务评测须另冻协议。已准备的stdio原型独立于模型原生调用探针：一张卡、私有会话、可观察的上下文上限和资源失败、固定预算、退出后释放GPU。其离线协议测试通过不代表已在真实模型/任务上验证；只有中性探针通过、模型指纹核验且显存再次满足条件时才考虑启动。
