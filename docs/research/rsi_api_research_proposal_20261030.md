# 新立项：API 条件下，递归改进是否具有超出经验复用的价值？

日期：2026-10-30。状态：研究立项与资源核验，**尚无新方法效果实验**。面向原计划中的 ICML 2027 目标，但不预判录用，不假定尚未核查的会议截止日期。

后续进展：API/CPU 的 P0 基线已完成，8题两遍合计16/16，初版任务触发饱和门槛；见[实际结果](rsi_p0_findings_20261030.md)。有限RL、模型/harness/训练环境协同更新与TTT的阶段条件见[扩展说明](rsi_model_harness_environment_extension_20261030.md)。下文资源探针与预算设计保留为立项时记录。

## 1. 立项结论

可以尝试 RSI，建议立项为**冻结模型权重、可修改改进程序的 agent 系统研究**。第一阶段只用 API 和 CPU，GPU 不是关键依赖。原 RL 项目已经完成归档；新项目复用可重放评测和版本管理经验，使用全新实验协议及任务来源。

推荐主问题：

> 在相同初始任务 agent、可访问历史经验及受控 API 预算下，让改进器递归改写自身，是否比固定改进器利用相同经验、以及固定外层优化器改写改进器，更有效地改进新的任务 agent？这种额外收益何时覆盖递归的获取和验证成本？

暂定英文题目：**Does Recursion Add Value Beyond Experience? Budgeted Self-Improvement of API Agents**。

研究对象是“改进程序”的持续变化。参数不变，所以使用 harness/program-level RSI 或 bounded recursive improvement 等限定称谓；不主张模型权重自举、无限自我加速或通用智能提升。若只有大模型替小模型重写提示，应称教师辅助的 agent 优化；只有新版本改进器实际参与产生下一代改进器，才有本项目所检验的递归路径。

这次文献核查没有证明该问题无人研究。其潜在价值在于**经验可访问性受控的递归对照、跨任务的改进器移植、完整成本核算，以及据此决定何时启用递归**。其中每个单独元素都有前作，不能把组合名称本身当创新。立项只支持一轮有退出条件的先导实验。

## 4. 最接近的前作与边界

以下是选题核查，不是论文性能复现。STOP、DGM、GEPA、Metaⁿ、AIDE² 主要核对原始摘要；HyperAgents 阅读了方法、移植实验和成本段落；Skill∞ 阅读了元任务定义、递归循环、分离设计和摊销段落；其他条目按原始摘要筛查。正式实验前应继续核对相应代码和全文差异。

| 原始来源 | 已有内容 | 对本项目的约束 |
|---|---|---|
| [STOP](https://arxiv.org/abs/2310.02304) | 固定 LM 的程序改进器改进自身 | “不更新权重也能自改”不是新发现 |
| [DGM](https://arxiv.org/abs/2505.22954) | 代码 agent 自修改与进化档案 | 代码自改＋保留成功版本不足以立题 |
| [GEPA](https://arxiv.org/abs/2507.19457) | 用轨迹反思优化提示 | 必须比较强固定优化器，而非只比原始提示 |
| [HyperAgents](https://arxiv.org/abs/2603.19461) | 任务 agent 和 meta agent 可编辑，测量跨领域改进能力 | 已有 imp@k、固定 meta 的移植对照；不能声称首次检验改进器 |
| [Metaⁿ](https://arxiv.org/abs/2608.24735) | 固定元操作递归处理产物，构建多层 agent | “层数更多”“递归上下文”已有直接路线 |
| [AIDE²](https://arxiv.org/abs/2609.26457) | 研究 agent 自改及跨任务迁移 | 不宜竞争大型自主科研系统的规模 |
| [Agent Plasticity](https://arxiv.org/abs/2610.08902) | 经验转化为持久能力，计入学习成本 | 成本—泛化曲线不是单独的新颖性 |
| [Skill∞](https://arxiv.org/abs/2610.35434) | 元技能递归优化，与任务技能分离后复用，讨论摊销 | **最直接前作**；不能把分离与摊销再次包装成方法 |
| [RSI on a Budget](https://arxiv.org/abs/2610.29121) | 评估前预测代码修改价值、预算内选择 | “低成本筛选候选”已有近邻 |
| [SpecRSI](https://arxiv.org/abs/2610.16491) | 协同安排修改与验证、学习改进器 | “预算感知递归”也不能空泛声称首次 |
| [Phantom Gains](https://arxiv.org/abs/2608.20290) | 未改变模型的测量零对照揭示假增益 | 需要重复未修改基线，不能把采样波动叫新能力 |
| [PAST-Bench](https://arxiv.org/abs/2608.04003) | 匹配条件下控制经验保留、检验跨会话增益 | 经验 on/off 和持久性本身不是新 benchmark 贡献 |

候选区别是：把**固定程序＋可更新记忆**、**固定外层程序优化 meta 程序**、**meta 程序递归自改**放在相同候选空间和受控信息/成本下，检验递归的增量价值，并研究何时应该将预算从直接任务优化转给元层。现阶段这是待验证的研究切口，不是已证明的新算法。若全文/代码进一步核查发现已被完整覆盖，应将其作为复现基线，不能靠换成小模型或 arXiv 领域继续声称创新。

## 5. 可证伪假设与两个不同的测量目标

设任务 agent 为 `s`，改进程序为 `m`，共享经验记录为 `h`，内层预算为 `b`。`Optimize(m,s,h,b)` 输出一个由验证集选择的任务 agent。外部独立测试得分记作 `S_test`。

**H1：改进器移植收益。** 在全新优化问题上，把任务 agent 重置为同一 `s0`，给定同一来源经验 `h` 和内层预算 `b`：

`Δ_transfer = E[S_test(Optimize(mT,s0,h,b)) - S_test(Optimize(m0,s0,h,b))]`。

该量只回答“所获改进器是否有用”。它不能单独证明递归有用，因为固定外层优化也可能产生同样好的 `mT`。

**H2：递归特有收益。** 在外层相同预算下，分别用固定 `m0` 和当前版本 `mt` 生成后继改进器；采用相同接纳机制，再在新的相同 `s0/h/b` 上移植比较。若递归不优于固定外层元优化，就不能归因于递归链。

**H3：完整成本下的价值。** 递归的获取、被拒候选、内层评测、记忆整理、重试、移植验证全部计入成本。报告总预算下的累计成功任务数及质量—成本曲线；免费额度下实际现金成本与可迁移的 token/调用成本分开报告。

移植对照与端到端对照必须分开：共享同一来源日志的移植实验控制可访问经验；各臂独立采集轨迹的端到端实验测完整系统收益。不能给控制臂事后补看处理臂产物，再把差值称为无条件因果效应。共享日志来自事前固定的公共探针，而非筛选后的递归成功轨迹；“相同信息”操作化为相同日志访问和上下文预算，不声称模型的内部理解也相同。

## 6. 最小实现与必要对照

任务 agent：小模型 API＋原生工具接口＋可编辑的任务提示/有界状态摘要。改进器：同一 API 模型执行可编辑的诊断、候选生成、取样与停止规则。先采用有界声明式配置和提示编辑；若进入程序修改阶段，编辑在隔离进程/容器中执行。评分器、任务清单、API 计费代理和总预算上限始终位于可编辑范围之外。

| 实验臂 | 改什么 | 解决哪个替代解释 |
|---|---|---|
| 原始任务 agent 重复运行 | 不优化 | API 漂移、采样噪声与初始能力 |
| 固定改进器＋共享经验/可更新摘要 | 任务提示/策略与经验摘要；改进控制程序固定 | 收益是否只来自经验积累 |
| 固定外层元优化 | `m0` 每轮优化任务 agent 与候选 meta；`m0` 自身不替换 | 改进器搜索有用是否等于递归有用 |
| 递归改进 | `mt` 产生候选 `m(t+1)`，接纳后用于下一轮 | 所检验的递归路径 |
| GEPA 或经核对的强固定优化基线 | 同一可编辑任务字段、同样可访问轨迹 | 是否只胜过过弱的人造固定改进器 |
| 选择性递归（第二阶段候选方法） | 根据独立开发探针的迁移收益决定是否花预算自改 | 是否优于固定比例/永远递归/完全不递归 |

主对照共用 LM 身份、候选空间、可见日志、上下文上限和评分器；不能只给递归臂强编辑器、更多候选或更长输出。预算主分析按总 token/计价成本封顶，同时报告候选数与工具调用数；跨 tokenizer 比较不把等 token 当等 FLOPs。

小模型同时担任 solver 和 improver 是起点。如果其诊断/编辑能力太弱，再增设同一大模型编辑器支持的固定/递归两臂；大模型不进入最终小模型执行链。这是教师辅助设置，应单列，不能混为纯小模型 RSI。额外的“直接大模型完成任务”可作成本能力参照，不是公平的同模型机制对照。

## 7. 任务设计：只复用工程，不复用旧测试证据

首个 CPU pilot 用两个可独立验算的任务域：

1. **SQLite 状态工作流**：读取约束、联表定位对象、执行带前置条件的状态更新，验证目标状态及无关数据未被破坏。涵盖幂等、撤销与约束冲突；不以特定 SQL 字符串相等作为正确性。
2. **本地表格/文件流程**：按数据内容发现 schema、连接/筛选/聚合、生成符合契约的产物；独立参考实现验证内容、schema 与文件副作用。不能把改文件名或实体名当作新任务血缘。

这两域是机制试验载体，不预设能构成新的 benchmark 贡献。生成器、目标关系与检查器先冻结；参考策略必须通过，always-finish/遗漏步骤/错误状态等负控制必须失败。验证器与参考解尽量不同实现，避免共同错误。

拆分层次：外层 meta-train / meta-dev / meta-test 优化问题；每个优化问题内部另有 task-train / task-val / task-test。外层按操作依赖结构、数据库/工具 schema 与任务家族分组；内层也不能只换随机 ID 后宣称 OOD。任务 agent 与可修改策略在跨问题时重置，只有声明的 meta 程序与来源经验可传递。最终 meta-test 及其 task-test 不能用于选择 meta 程序或调节递归门槛。

后续外部效度候选是 [AppWorld 官方环境](https://github.com/StonyBrookNLP/appworld)：另核实依赖、许可证、任务划分和 API 成本后固定版本。它不是第一阶段的必装依赖。不能只在自造低难度任务上赢几题就宣称一般 RSI；至少还需外部环境和第二个实际可用模型的复核。

旧 arXiv 目录、BFCL 题库、旧 final、历史错误轨迹仅作工程回归/开发经验；不进入新项目独立验证证据。历史 0/24 只能动机化“检查工作流回归”，不能预告新方法成功。

## 8. 候选方法：根据可迁移增益决定是否递归

先导结果若支持 H1/H2，再实现一个简单而可审查的调度器：将下一个预算块分配给“直接优化任务策略”或“递归优化 meta”。用独立的 meta-dev 优化问题估计两种动作的后续收益；计入 meta 产生与验证的额外成本、剩余待处理问题数和小模型当前 headroom。第一版用固定、预先声明的门槛或 CPU 统计模型，不用 RL 训练大网络。

示意规则：只有估计的后续累计增益超过本次递归的成本与不确定性余量，才启动递归；否则将剩余预算给固定改进器。必须与等总预算的固定比例、全部直接优化和全部递归对比。这个调度规则本身先保持固定；否则无法分清调度改进与 meta 改进。

若在相同目标质量 `τ` 下，固定优化每个新问题耗费 `c0(τ)`、进化后耗费 `cT(τ)`，meta 获取费用为 `Cmeta`，且 `c0>cT`，则描述性的盈亏平衡问题数为 `ceil(Cmeta/(c0-cT))`。若质量不可匹配或差值不正，不能强算一个正的回本次数；应报告质量—成本前沿。该核算不是新理论，候选贡献必须来自受控机制证据和可泛化的分配改进。

## 9. 首轮预算、阶段与停止线

以下是设计预算，不是已发生花费；主实验协议须在任务生成器、模型可用性和计量验证后另行冻结。本轮仅消耗连通性探针。

| 阶段 | 内容与规模 | GPU | 退出条件 |
|---|---|---|---|
| P0 接口/评分标定 | ≤100 次短 API 调用；≤0.3M input、0.05M output token；只用开发探针 | 0 | 工具格式/验证器未通过，先修基础设施；成功率长期低于20%或高于85%时只在开发池调难度，随后冻结 |
| P1 机制可行性 | 固定经验、固定元优化、递归三臂；3条独立进化链、3代；源域2个优化问题，每代最多2个meta候选，内层最多2候选×4题 | 0 | ≤10,000 API调用、≤30M input/5M output token；任何上限先到即停止，未完整运行不冒充完成对照 |
| P1 移植检查 | 保留部分预算给未用的开发家族；相同新solver起点、同经验和同内层预算 | 0 | 递归不优于经验对照和固定元优化则停止扩大递归框架；3链仅探路，不宣称显著 |
| P2 有条件扩展 | 确有信号后加 GEPA、官方/忠实复现的最近前作、第二模型、外部环境、≥5条独立进化链与多个预算点 | 0为默认 | 有差异化才投入；论文规模依据先导方差/功效分析确定，5链并非自动足够 |

P1 源域评测数量的量级为 `3臂×3链×3代×2meta候选×2源问题×2内层候选×4题=864` 个 task episode，尚未计入初始标定、修改请求和移植评测。每个 episode 若需6次模型调用，仅此项就达5,184次。**无 GPU 不等于低 API 成本**；必须先测平均上下文长度和重试率，再决定是否达到上述上限。大模型首轮预算为0；若加入教师对照，先按其真实价目和上下文确定独立上限，不能把“小模型几乎不限”外推成大模型无限授权。

统计以进化链与任务家族为独立/分层单位，报告逐链结果与配对差异区间；不能把几千个相关工具步当独立样本。按区组交错请求以减少 API 时间漂移影响；相同随机种子不保证云 API 相同随机流。no-op 重复比较估计噪声，正式结论所需重复数根据先导方差确定。超时、拒绝、截断、格式错与真实任务失败分别记录，不选择性删除失败运行。

判定支持递归至少要同时满足：健康可调用基线；移植收益超出未修改噪声；优于固定元优化；优势不只来自更强教师/更大运行预算；完整成本下对至少一种明确部署场景有价值。只见总分上涨不够。
