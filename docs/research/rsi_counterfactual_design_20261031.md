# 递归增量的反事实设计草案（2026-10-31）

状态：设计草案；还没有健康基线、可报告的递归效果，亦未冻结最终实验。针对 Skill∞、HSI 和 GEPA 已覆盖的内容，研究重点是区分“元策略变好了”与“使用当前元策略产生下一代是否本身有额外价值”。

## 干预与可识别量

设 solver 指令为 H，初始 improver 为 M0，当前 improver 为 Mt，共享可见训练历史为 E。构造共享状态 `(H, Mt, M0, E)`；调用同一模型、相同工具与输出上限，在该状态下随机/交错地请求一次 improver 候选：

- fixed-outer：由固定 M0 作为提出者，目标是修改 Mt；
- recursive：由当前 Mt 作为提出者，目标也是修改 Mt。

若 Mt=M0，两组模型请求相同（代码测试已验证），不可能在首个元更新上识别出递归政策差异。只有先以训练数据获得 Mt≠M0，再把同一状态与历史移植到两组，才有可观察的处理差异。历史 E 中可见字段和大小应完全相同，原始参考解、检查器及锁定任务标签不可进入。该移植干预衡量“给定这个共享状态时的下一步提出者效应”；它不自动等于从头独立训练整条递归链的总效果。

对每个候选 improver，重置到同样的初始 solver、任务与内层预算，让它在多组 meta-train 问题上提出 solver 候选；按预先冻结的训练/选择规则评估，再使用独立留出的 inner-audit 汇总其对 solver 优化的增益。拒绝无效输出、超长/空白、未通过检查的候选；不以模型自评打分。各臂有同等候选数上限、经验访问和 verifier 调用。候选没达到晋升门槛是实验结果，不能重采直至成功而不计费。

独立端到端对照另起多条链：固定经验（M0，不更改M）、固定外层（M0更新M，当前M改H）、递归（当前M更新M和H）。固定经验组可将相同总预算用于更多直接 H 搜索，而不是人为闲置预算。所有生成、失败、重试、筛选、验证及模型调用计入各链；相同历史的移植分析与独立链结果分开报告。

## 数据、成本与不确定性

按生成器分组的 meta-train/meta-dev/meta-final 只是第一道隔离；共享应用、API和语义操作使其不能自动宣称 OOD。训练候选的选择、预算和门槛只使用训练/开发信息。最终协议冻结后，每个最终优化问题可向各方法开放相同的 inner-train/selection 信息，但其 inner-audit 标签只能由独立评测器使用，不能反馈给元策略、其他最终问题或后续选择。若无法保证这点，不能把它称为独立最终评估。

成本至少记录 input token、output token、API尝试/重试、环境基础调用和真实墙钟时间。服务端模型别名和未知 usage 需单列。没有可靠价格时用这些原始量及质量—成本前沿，不擅自换算美元；若使用价格权重，记录来源、时间与敏感性分析。比较回本时把 M 的获取和筛选成本计入，且在目标质量不同或单位收益非正时不能强算正回本次数。

统计单位是独立进化链及任务生成家族，任务内多个实例/步骤不是独立复本。报告每条链和每个家族的配对结果及区间；现有8个锁定最终生成器对小效应的分辨率有限，不能事后以多步轨迹充当更多样本。正式样本数、重复数和统计分析应依据训练/开发方差另行确定；三条链仅作先导。

## 当前执行门槛

本草案不授权访问 meta-final，也不改变进行中的固定基线。只有接口、基线成功率和独立回放达到先导要求，才冻结首次等预算执行协议；若近期两题开发控制有收益，也只能称为模型/提示/接口组合的开发可行性结果。上述问题与 Skill∞ 的递归元技能及 HSI 的固定外层元优化高度相邻，能否构成新方法贡献仍待实验证明。
