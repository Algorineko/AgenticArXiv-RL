# GRPO 受管恢复边界

本文说明 `containerized-experiment-management` 的 GRPO 附加恢复状态。
它补充通用 checkpoint 契约，不把模型重载、控制状态测试或文件存在解释为真实训练恢复成功。

## 与原训练入口的关系

非受管 GRPO 入口的默认保存、采样和损失参数保持不变。受管恢复必须明确指定已完整提交的 checkpoint，并写入新的 attempt 目录；不能直接把旧输出目录作为新尝试输出。

恢复消耗原计划剩余预算，不重置总步数、学习率计划或奖励课程。原始冻结参考始终是本次训练最初绑定的 SFT/DPO 起点，而不是 checkpoint 中已更新的策略。

受管运行在构建策略前先使用配方的共同 `seed`，避免完整 SFT/DPO 模型新建 LoRA 时受各进程先前随机流影响。TRL 随后仍按原接口设置各 rank 的生成随机流，不将生成种子强制合并。绑定初始冻结参考后先收集各 rank 的实际权重指纹并一致拒绝差异，标准 Trainer 完成 DDP 包装和恢复后再于 `on_train_begin` 核对；因此不能让 DDP 广播静默改变已绑定的参考。非受管入口不新增提前设种子行为。

全参数路径重建正确来源的冻结参考前，先解除旧参考在 Trainer 与 Accelerator 中的引用并回收。固定 Accelerate `1.11.0` 没有单模型注销接口，因此仅删除 `_models` 中与旧参考或其解包对象身份相符的注册，再调用公共内存回收接口；不调用会清空所有模型、优化器、调度器和数据加载器的 `free_memory`。不能确认旧参考注册时拒绝继续，不冒险留下两份参考模型。

QLoRA 的 `default` 策略保存在 checkpoint 根目录，原始冻结 `ref` 保存在子目录。固定 Transformers `4.57.6` 在存在 adapter 子目录时会跳过根策略，因此受管恢复在标准模型加载边界显式补载根 `default`，随后校验冻结参考指纹；该步骤先于优化器恢复和首次 rollout，不改变非受管入口。

标准加载 `ref` 和补载根 `default` 的整个边界均关闭 PEFT 的自动精度转换，避免 BF16 adapter 被静默升成 FP32。加载结束后、优化器状态恢复前，检查参数对象、精度、冻结状态、活动策略和优化器引用不变；不能只保护最后一次策略补载而遗漏标准参考加载。

受管运行同时支持显式优化步数预算和原有 epoch 预算。使用 epoch 时保留原 `epochs` 与 `max_steps=-1`，不把它转换为另一套算法参数；首次尝试在 Trainer 建立真实数据加载器后、第一次优化前，核定并绑定 `state.max_steps` 为原计划总优化步数。恢复仍保留相同 epoch 配置和核定总步数，剩余工作由标准 Trainer 的已完成 epoch 与批次跳过机制承接。结果中的 `planned_steps`/`total_budget` 使用真实核定步数，不能用 `-1` 或缺失值宣称预算已完成。

## 按 rank 保存的附加状态

- TRL 微步计数、生成复用窗口的消费位置，以及尚未消费的生成缓存。缓存包含后续更新需要的旧策略等信息，不能用重新生成替代。
- `RepeatSampler` 的局部随机状态及当前 epoch 的起始排列状态。epoch 中途恢复重建同一索引排列，再由标准 Trainer 跳过已消费批次；epoch 完整结束后恢复则使用下一次排列的状态。索引跟踪不改变采样分组、生成复用次数或全局随机流。
- 奖励课程的逻辑训练步数和原始冻结参考身份。
- 零方差保护的累计次数、停止标志及停止步数；Canary 的累计退化次数、历史结果及停止标志。
- 影响后续汇总的奖励统计与审计计数。

适配器限定 TRL `0.29.1` 和已检查的内部接口，当前不支持 vLLM 或动态同步参考模型。升级 TRL、改变 rank/卡数映射、生成复用参数或课程配置不能按普通恢复继续。缺少当前窗口仍需使用的缓存、未知状态版本、参考身份不一致或保护器已经停止时，应在后续 rollout/更新前拒绝恢复，而不是清零状态后继续。

接口依据为固定标签的 [GRPOTrainer 源码](https://github.com/huggingface/trl/blob/v0.29.1/trl/trainer/grpo_trainer.py)、[RepeatSampler 源码](https://github.com/huggingface/trl/blob/v0.29.1/trl/trainer/utils.py)及 [Transformers Trainer 源码](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/trainer.py)，不是动态最新版本的默认行为推断。

附加状态不是完整 checkpoint 的替代品。策略、优化器、调度器、数据消费位置、随机状态及适用的精度状态仍须由通用保存事务完整提交，并通过文件指纹校验。

保留标准 Trainer 返回的原始 `training_loss` 语义。固定版本在恢复时重置其局部损失累计量，因此该返回值不能作为跨 attempt 的运行累计均值，也不能作为等价恢复证据。受管诊断明确记录这一限制；无法可靠取得的本尝试累计损失与均值标为 `null`，不按累计步数估算。

## 新尝试与审计边界

恢复后的轨迹、统计、日志和 TensorBoard 输出属于新 attempt。旧 attempt 的轨迹文件保持只读，不因审计器初始化被清空。

已提交 checkpoint 的逻辑边界与恢复来源必须保留。中断后尚未提交的计算可能需要重算，但不能把它重复计为已提交训练进度，也不能把失败尝试生成量从资源消耗记录中抹去。旧 attempt 的用户停止请求不在新 attempt 再次生效，训练保护状态则必须承接。

受管成功出口统一依据已记录的训练终态，而不只检查是否少于预算步数。零方差保护即使恰好在最后预算步进入 `converged`，也保留 `protection_stopped`，不导出成功 `final`、不进入正常阶段验证、不覆盖为 `budget_completed`。非受管入口的既有导出行为不变。

## 本地工程验证与剩余门禁

`tests/test_grpo_managed_resume.py` 使用无模型的控制状态、缓存张量和控制索引，检查状态文件往返、真实 TRL 采样器包装的索引一致性、epoch 恢复边界、拒绝路径及保护累计承接；不调用模型生成、不创建研究轨迹，也不证明优化轨迹或模型权重等价。

同一测试文件还使用微型线性层和真实 PEFT/Trainer 保存与加载接口，验证 BF16/FP32、safetensors/bin 两类保存格式下根策略与冻结参考的双 adapter 权重恢复，以及参数对象、精度和优化器引用不变；没有模型下载、量化训练或生成，不能替代真实 QLoRA GPU 恢复门禁。

`tests/test_grpo_reference_initialization.py` 使用 CPU 微型 PEFT 层检查不同进程先前随机流下的初始参考一致性、原始 seed 区分和非受管随机流保持，并验证跨 rank 指纹汇总拒绝边界。真实 Accelerator 的微型模型注册及弱引用检查确认旧参考在新参考创建前已被回收，而策略、优化器和其他登记不变；这不是 GPU 峰值显存或实际 DDP 训练验证。

`tests/test_grpo_completion_boundary.py` 使用真实默认流程回调、零方差保护和生产完成边界，检查最终步保护与预算完成同时发生时不会发布成功产物，并保留其他停止原因、正常完成及非受管行为。检查仅涉及控制状态，没有执行训练或写入模型。

真实恢复门禁仍需另行授权，在单卡和四卡分别进行固定总预算的连续运行、完整保存后恢复和强制中断后恢复对照。需核对生成缓存消费、数据位置、随机状态、学习率、策略/原始参考关系、奖励课程、保护状态及审计边界，并预先声明浮点容差。

本轮未操作服务器、未启动真实训练，也未执行真实单卡或四卡恢复门禁。
